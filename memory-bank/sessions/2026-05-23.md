## Work Done

### 1. Fixed Folder Context Overload (T13)
- **Problem**: When a folder or tag was attached as context, `ContextEngine.ts` read the full contents of every file in that folder, causing massive token bloat and context overload.
- **Solution**: Folder and tag context items now return a **file listing with tool-usage instructions** instead of reading full file contents. The LLM is instructed to use `list_notes` or `read_note` if it needs specific file contents.
- **Files**: `src/context/ContextEngine.ts`

### 2. Enhanced `list_notes` Tool (T13)
- **Added parameters**:
  - `include_subfolders` (boolean, default `true`) — whether to include files from subfolders
  - `depth` (number, default `1`, max `3`) — how many levels of subfolders to traverse
- **Return value**: Now includes `subfolders` array alongside `files` array, giving the LLM visibility into folder structure.
- **Files**: `src/agent/tools.ts`, `src/agent/ToolExecutor.ts`

### 3. Fixed `count_notes` Accuracy (T13)
- **Problem**: `count_notes` was reporting misleading totals when subfolders contained many files — the count didn't distinguish between direct files and recursive totals.
- **Solution**: Now reports five distinct counts with human-readable breakdowns:
  - `totalCount` — all files recursively
  - `markdownCount` — all `.md` files recursively
  - `directCount` — files directly in the queried folder
  - `directMarkdownCount` — `.md` files directly in the queried folder
  - `subfolderCount` — number of immediate subfolders
- **Files**: `src/agent/ToolExecutor.ts`

### 4. Updated System Prompts (T13)
- `buildSystemPrompt()` in `ChatApp.tsx` now describes the enhanced `list_notes` and `count_notes` capabilities so the LLM knows to use them effectively.
- **Files**: `src/components/ChatApp.tsx`
