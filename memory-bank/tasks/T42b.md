# T42b: Atomic Writes for Session Uploads

*Created: 2026-08-19*

## Objective

Implement atomic write pattern for WebDAV session uploads to prevent corrupted files on interrupted transfers.

## Background

Obsidian-ai's `WebDAVStorageAdapter.putSession()` writes directly to the final path. If the upload is interrupted (network failure, app killed), the server has a partial/corrupted JSON file. SyncIt solves this by writing to a temp path first, then MOVING to the final path.

## Implementation

### Pattern
```typescript
async putSession(session: EncryptedSession): Promise<PutResult> {
    const tempPath = `${this.prefix}sessions/${session.id}.json.tmp`;
    const finalPath = `${this.prefix}sessions/${session.id}.json`;
    
    // 1. Write to temp
    await this.request('PUT', tempPath, { body: payload });
    
    // 2. Atomic move
    await this.request('MOVE', tempPath, {
        headers: {
            'Destination': this.baseUrl + finalPath,
            'Overwrite': 'T'
        }
    });
    
    return { etag: ... };
}
```

### Cleanup
- On init: scan for `.tmp` files and delete (cleanup from interrupted writes)
- On error: attempt to delete temp file

## Acceptance Criteria
- [ ] Interrupted upload leaves no corrupted session file
- [ ] Temp files cleaned up on next sync or plugin load
- [ ] No performance regression (MOVE is cheap)
