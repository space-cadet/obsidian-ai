# T66: Stylesheet Architecture and CSS Cleanup

*Created: 2026-08-30*
*Last Updated: 2026-08-30 22:03:24 IST*

**Status**: 🔄 **IN PROGRESS — source refactor and cleanup complete; visual verification remains open**
**Priority**: MEDIUM
**Dependencies**: T8a, T34, T41, T58d

## Description

Give the shipped stylesheet a responsibility-led source structure and remove
verified CSS maintenance debt without changing the plugin's visual contracts.
The baseline root `styles.css` was 5,064 lines and served chat, profiles,
settings, updater, participant, sync, progress, and utility UI.

## Implementation Status

The structural refactor and conservative cleanup were implemented and pushed
to `main`. The remaining open item is the Android/Obsidian Settings card-width
verification: four follow-up CSS attempts changed the settings wrapper or its
gutters, but the supplied before/after screenshots showed no meaningful change
to the card boundaries. The last attempt also made the prompt textareas appear
misaligned; the fixed `min-width: 25em` on `.wide-text-settings` is now the
first concrete regression to correct in a new session.

## Progress

1. ✅ Captured the selector-family and release-artifact baseline.
2. ✅ Split the stylesheet into six ordered source partials and added the
   deterministic `prebuild` concatenation step.
3. ✅ Preserved the tracked root `styles.css` release artifact and verified
   package output under `dist/chat-lab/`.
4. ✅ Removed verified duplicate rules and replaced unsupported
   `attr(data-agent-color)` with a typed CSS custom property for agent bubbles.
5. ✅ Verified TypeScript, production build, package output, 48 test files /
   433 tests, and `git diff --check`.
6. 🔄 Complete real desktop/mobile visual verification and identify the actual
   Obsidian Settings width owner.

## Scope

- Inventory selector families and assign ownership to feature areas.
- Decide whether authored CSS should remain in one file or be split into
  source partials merged in a deterministic order.
- Preserve cascade order, theme-variable behavior, responsive behavior, and
  Obsidian mobile compatibility.
- Remove duplicate declarations and unnecessary `!important` after checking
  the selectors' actual dependency on cascade precedence.
- Review unsupported or preview-only features separately from shipped plugin
  CSS, including the prior `css-scrollbar`, `css3-attr`, and
  `css-text-indent` findings.
- Preserve the root `styles.css` release artifact and the release asset
  contract.

## Out of scope

- General visual redesign.
- Sync behavior changes owned by T58/T58d.
- Updater behavior changes owned by T41.
- Settings UX changes owned by T34.
- Reopening the completed inline-style remediation in T8a except for a
  regression found during verification.
- Broad TypeScript decomposition; those findings are recorded in the dated
  monolithic-files audit.

## Implementation order

1. Capture the current selector-family and release-artifact baseline.
2. Define source ownership and a deterministic merge/import strategy.
3. Make one low-risk structural slice at a time, preserving selector names
   unless a migration is explicitly tested.
4. Remove verified duplicate and `!important` debt.
5. Review shipped versus preview-only CSS and document compatibility decisions.
6. Verify chat, settings, profiles, updater, participant, sync, and responsive
   surfaces on desktop and mobile.

## Acceptance criteria

- [x] Every shipped selector family has a documented source owner.
- [x] The final root `styles.css` is produced deterministically and contains
      all required feature styles.
- [ ] No unreviewed cascade-order or responsive regressions are introduced.
- [x] Duplicate declarations and unnecessary `!important` uses are either

- [x] Unsupported/preview-only CSS is isolated or documented separately.
- [ ] Focused UI checks and desktop/mobile visual acceptance are complete;
      the full test suite, TypeScript, and production build pass.
- [x] Release packaging still contains the expected `styles.css` artifact.
