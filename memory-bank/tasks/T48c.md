# Task: T48c — Rolling Conversation Summary and Compaction
*Created: 2026-08-23 02:02:32 IST*
*Status: 🔄 ACTIVE*
*Last Updated: 2026-08-29 11:25 IST*

## Objective
Summarize older conversation turns when the token budget is exceeded, while
preserving recent turns, decisions, user intent, open questions, and useful tool
outcomes.

## Acceptance Criteria
- [x] Token threshold is primary; message count is a guard for a valid summary prefix.
- [x] Recent turns are retained verbatim in the model-history projection.
- [x] Older turns become a structured JSON-derived summary rendered into the system prompt.
- [ ] Compaction preserves all tool context needed for follow-up actions; pairing coverage remains open.
- [x] Full transcript remains visible and exportable.
- [x] Compaction is observable and does not block the active request unnecessarily.
- [x] The newest 3–5 messages are preserved verbatim (default: 4).
- [x] Summaries request decisions, constraints, user intent, open work, and tool outcomes.
- [x] Summaries are marked as derived context, not authoritative user text
- [ ] Exact older messages/tool results remain retrievable when precision matters
- [ ] The agent asks for clarification rather than inventing omitted historical detail

## Exact retrieval tool contract — 2026-08-25

- `read_past_message(session_id, message_id)` returns the exact persisted message.
- `read_tool_result(session_id, tool_call_id)` returns the complete persisted
  result rather than a search snippet or compacted replay.
- Both retain source IDs and provenance, exclude the active in-flight message,
  and participate in T60's availability, validation, approval, and replay rules.
- T60b/T60c own transport and execution correctness; this task owns retrieval
  semantics and compaction acceptance.

## Architecture Review Update — 2026-08-27

The proposed model-history module must preserve T48c ownership of compaction,
derived summaries, and exact historical retrieval. T46's physical extraction
and T46a's turn coordinator may consume this policy, but neither should add a
parallel compaction or retrieval rule.

## Local acceptance update — 2026-08-29

Compaction responses are now accepted only when all four requested fields are
arrays of text. The summary prompt labels message IDs as source references,
includes tool-call IDs, and the rendered result says it is a derived summary
that should be checked against the full transcript. Focused tests cover these
rules and legacy tool-call records.

Exact historical retrieval, clarification behavior, and pairing through a
completed compaction cycle remain open. They need the plugin/provider test
path and the retrieval design described above.
