# T42c: Concurrency Control for Parallel Sync

*Created: 2026-08-19*
*Parent: T42*
*Status: 🔄 PENDING*
*Priority: P1*

## Objective

Add concurrent upload/download support to obsidian-ai sync, replacing the current sequential session-by-session approach.

## Background

Obsidian-ai's `SyncEngine.sync()` processes sessions one at a time. With 20+ sessions on a slow connection, this is painful. SyncIt uses `runWithConcurrency()` to process up to N files in parallel (default: 3).

## Implementation

### Generic Concurrency Utility
```typescript
async function runWithConcurrency<T, R>(
    items: T[],
    concurrency: number,
    fn: (item: T) => Promise<R>
): Promise<R[]> {
    const results: R[] = [];
    const executing: Promise<void>[] = [];
    
    for (const [i, item] of items.entries()) {
        const p = fn(item).then(r => { results[i] = r; });
        executing.push(p);
        
        if (executing.length >= concurrency) {
            await Promise.race(executing);
            executing.splice(executing.findIndex(p => p === p), 1);
        }
    }
    
    await Promise.all(executing);
    return results;
}
```

### Integration
- Add `concurrencyLimit` to `RemoteStorageConfig` (default: 3)
- Use in `SyncEngine.uploadSessions()` and `downloadSessions()`
- Respect cancel flag between batches
