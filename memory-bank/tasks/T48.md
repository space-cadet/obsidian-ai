## Description

Implement token-budgeted model-context management for long conversations. The
current message-count replay resends large system prompts, history, tool results,
and attachments without semantic compaction. The model should receive a compact
history while the user retains the complete local transcript.

The strategy combines a request budget, bounded tool-result replay, canonical
model-history serialization, and periodic replacement of old turns with a
condensed summary.

## Acceptance Criteria

- [ ] Compaction triggers automatically after N turns (configurable, default 5)
- [ ] Older turns are summarized into a single system-injected summary message
- [ ] Recent turns (configurable, default last 3) are kept in full fidelity
- [ ] Summary preserves key decisions, tool call outcomes, and user intent
- [ ] Compaction runs asynchronously (does not block the chat UI)
- [ ] Users can see that compaction occurred (visual indicator in chat)
- [ ] Works with all providers (DeepSeek, OpenAI, Anthropic, etc.)
- [ ] Compatible with tool calling (summarizes tool results, doesn't break tool context)
- [ ] Request builder reserves space for system prompt, tools, current input, response, and tool output
- [ ] Full UI/export history is separated from bounded model replay history
- [ ] Large tool results and attachments have token-based replay limits
- [ ] Provider-reported usage is shown separately from fallback estimates

## Implementation Details

### Compaction Algorithm

```
Before each request and after every N user turns:
  1. Build a token-budgeted request from system prompt, tools, input, attachments, and history
  2. Identify turns to summarize: messages[0 : -keepRecent]
  3. Send these turns to a "summarization" LLM call (same provider, fast model)
  4. Replace the summarized turns with a single message:
     role: "system"
     content: "[Prior conversation summary: {summary}]"
  5. Preserve the last "keepRecent" turns in full while retaining the full display transcript
```

### Key Design Decisions

- **Summarization model:** Use the current provider's fast/cheap model (e.g., DeepSeek-V4-Flash) rather than the main model to minimize cost of compaction itself
- **Summary format:** Structured markdown with sections: Key Decisions, Tool Results, User Intent, Open Questions
- **Tool call preservation:** Include a note like "Used read_note on [[Physics Notes]], found: ..." rather than full tool call JSON
- **Trigger conditions:** Compaction fires after N turns OR when estimated payload exceeds a threshold (e.g., 200K tokens)

### Integration Points

- Hook into `useMessageActions.ts` after each successful assistant response
- Check if `messages.length >= compactionThreshold`
- If yes, fire async compaction before the next user message is sent
- Update `messagesRef.current` with compacted history
