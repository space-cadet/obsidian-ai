## Description

Define a common, security-conscious architecture for authenticating with
external AI services and subscription-backed coding assistants from Obsidian
AI. The umbrella covers service-specific adapters such as Codex and Claude
Code while keeping ordinary API-key providers separate from account-based or
locally authenticated service sessions.

This task is separate from T39. T39 covers installed Obsidian peer plugins
that contribute domain tools; T69 covers external service authentication,
local service processes, provider sessions, and model-facing adapters.

## Acceptance Criteria

- [ ] Define a common adapter boundary for account login, logout, re-auth,
  status, service requests, streaming, and session cleanup.
- [ ] Record the official or supported authentication surface for each service
  before implementation; do not assume that a subscription login is API access.
- [ ] Keep API keys, OAuth credentials, refresh tokens, callbacks, and local
  service details out of prompts, model context, debug logs, exports, and sync.
- [ ] Preserve a clear distinction between API-key access, local CLI/app-server
  access, and direct account/OAuth access in settings and diagnostics.
- [ ] Define desktop/mobile availability, consent, logout, re-authentication,
  failure, cancellation, and credential-storage behavior for each adapter.
- [ ] Reuse the existing provider-profile, tool, approval, streaming, and
  lifecycle boundaries without changing T39's peer-plugin contract.
- [ ] Add service subtasks and implementation notes before any source-code
  implementation begins.

## Implementation Details

- T69a covers Codex / ChatGPT subscription authentication, with local
  `codex app-server` as the preferred initial architecture.
- T69b covers Claude Code authentication and must first verify the supported
  CLI, account, subscription, and programmatic integration boundaries.
- Future services receive separate T69 subtasks only after their authentication
  and execution surface has been identified.
- The shared design and decision record is
  `memory-bank/implementation-details/external-service-authentication.md`.
