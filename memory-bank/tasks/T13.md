## Description

Enable the LLM to directly edit, create, and append to Obsidian notes via native tool calling using the Vercel AI SDK. Instead of returning edited content as text for the user to manually apply, the agent invokes structured tools that modify the vault directly — similar to how agentic code IDEs (Cursor, Claude Code) operate.

The user retains control via an `autoApply` setting (off by default): when off, each tool call is surfaced as a pending action in the chat UI that the user must approve before execution.

## Architecture

```
User: "Rewrite the intro of @Vocabulary Log"
        │
        ▼
ChatApp creates inline tool loop (messages, tools)
  │
  ├── buildSystemPrompt()  → includes tool descriptions
  ├── resolveContextItems() → context XML block
  └── loop streamText({ tools, stopWhen: stepCountIs(1) })
        │
        ▼
  text-delta → "I'll rewrite that for you..."
        │
        ▼
  tool-call → edit_note({ path: "Vocabulary Log", content: "..." })
        │
        ▼
  ChatApp renders pending tool UI inline:
    "✏️ Edit Vocabulary Log   [Approve] [Reject]"
        │
        ├── User clicks [Approve]
        │   ToolExecutor.edit_note() → vault.modify()
        │   Result appended to messages
        │   streamText called again (next step)
        │   LLM continues: "Done! I've tightened the intro..."
        │
        └── User clicks [Reject]
        │   Rejection appended to messages
        │   streamText called again
        │   LLM continues: "Understood, I won't modify the note..."
```

## Design Decisions (Robustness-First)

1. **Manual loop around `streamText`** — `ToolLoopAgent` is experimental. We own the loop.
2. **Pure Zod schemas (no `execute`)** — LLM interface separate from vault operations.
3. **SDK-agnostic `StreamEvent` union** — If v7 changes event shapes, only `api.ts` changes.
4. **`resolveNote()` three-tier resolution** — exact path → `.md` append → `metadataCache.getFirstLinkpathDest()`. Matches Obsidian's own link resolution.
5. **`patch_note` uses literal string matching** — not regex, to avoid unexpected replacements. `replace_all` uses `split().join()`.
6. **`edit_section` splits on newlines** — searches for heading lines starting with `# ` to find target section.

## Context

The Vercel AI SDK v6.0.174 (currently installed) removed `maxSteps` from `streamText` and introduced `ToolLoopAgent` as an experimental abstraction. For robustness, we avoid `ToolLoopAgent` and instead call `streamText({ tools, stopWhen: stepCountIs(1) })` repeatedly, managing the loop ourselves. This insulates us from experimental API churn.

Key SDK references:
- `streamText` with `tools`: https://ai-sdk.dev/docs/ai-sdk-core/tools-and-tool-calling
- `tool` helper: defines Zod schema (no execute for approval flow)
- `fullStream`: yields `TextStreamPart` union (text-delta, tool-call, tool-result, tool-error)

## Notes

- **arxivite does NOT have this feature** — its "tool registry" is imperative intent routing (app decides which function to run), not LLM-native tool calling.
- **Provider support**: OpenAI, Anthropic, Google Gemini, and DeepSeek all support tool calling. OpenRouter passes through to underlying model. Ollama support varies by model (Llama 3.1+, Qwen 2.5+ work well).
- **Bundle impact**: Minimal — `zod` is already installed, no new runtime dependencies.
- **Crash note**: The blank-screen crash is a **native Chromium renderer crash** (`SIGTRAP`/`EXC_BREAKPOINT`), not a JS exception. It occurs immediately after streaming completion when `StreamingBubble` unmounts and `MessageBubble` mounts. All defensive logging shows `MarkdownRenderer.render` resolves successfully. Working theory: Chromium/Electron bug triggered by rapid DOM mutations concurrent with smooth-scroll animation.
