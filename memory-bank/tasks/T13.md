## Description

Enable the LLM to directly edit, create, and append to Obsidian notes via native tool calling using the Vercel AI SDK. Instead of returning edited content as text for the user to manually apply, the agent invokes structured tools that modify the vault directly — similar to how agentic code IDEs (Cursor, Claude Code) operate.

The user retains control via an `autoApply` setting (off by default): when off, each tool call is surfaced as a pending action in the chat UI that the user must approve before execution.

## Completion Criteria

### Tool Definitions
- ⬜ `edit_note` tool — replaces full note content (calls `vault.modify`)
- ⬜ `append_to_note` tool — appends content to end of note (calls `vault.modify`)
- ⬜ `create_note` tool — creates new file (calls `vault.create`)
- ⬜ `read_note` tool — reads note content for the agent's context (calls `vault.read`)
- ⬜ Zod schemas for all tool parameters (`path`, `content`, `noteName`)
- ⬜ Tool descriptions tuned so the LLM knows when to use each tool

### API Layer
- ⬜ Restructure `ChatApiManager.streamChat()` to accept `tools` and `maxSteps`
- ⬜ Handle `toolCalls` / `toolResults` lifecycle inside the streaming loop
- ⬜ Yield structured `StreamEvent` types (text, tool-call, tool-result, error) instead of plain strings
- ⬜ Provider compatibility check — disable tools for providers/models that don't support function calling

### Chat Loop & UI
- ⬜ `ChatApp.handleSend` passes tools to `streamChat`
- ⬜ Streaming state machine handles text + tool events in sequence
- ⬜ Pending tool calls render as action cards in the chat stream ("Edit Vocabulary Log? [Approve] [Reject]")
- ⬜ On approve: execute tool, show success notice, continue stream
- ⬜ On reject: skip tool, inform model, continue stream
- ⬜ Tool results are fed back into the conversation history for model continuation

### Settings
- ⬜ `autoApply: boolean` setting (default `false`) — when true, tools execute without confirmation
- ⬜ `maxAgentSteps: number` setting (default `5`) — limits tool call roundtrips per message
- ⬜ Per-provider capability flags (`supportsToolCalling`)

### System Prompt
- ⬜ Dynamic system prompt includes tool availability description
- ⬜ Prompt instructs model to return ONLY revised content when using `edit_note`
- ⬜ Prompt clarifies that `read_note` is available for multi-step reasoning

### Safety
- ⬜ Tool execution errors surface as user-visible notices, not silent failures
- ⬜ `maxSteps` hard cap prevents infinite tool loops
- ⬜ Tool handlers validate paths (no directory traversal outside vault)
- ⬜ Create-note tool prompts overwrite confirmation if file exists (when autoApply is off)

## Architecture

```
User: "Rewrite the intro of @Vocabulary Log"
        │
        ▼
ChatApp.handleSend()
  │
  ├── buildSystemPrompt()  → includes tool descriptions
  ├── resolveContextItems() → context XML block
  └── plugin.chatapi.streamChat(messages, tools, maxSteps)
        │
        ▼
  LLM streams text → "I'll rewrite that for you..."
        │
        ▼
  LLM emits toolCall → edit_note({ path: "Vocabulary Log.md", content: "..." })
        │
        ▼
  ChatApp renders PendingToolCard:
    "✏️ Edit Vocabulary Log   [Approve] [Reject]"
        │
        ├── User clicks [Approve]
        │   ToolExecutor.edit_note() → vault.modify()
        │   Result fed back to LLM
        │   LLM continues: "Done! I've tightened the intro..."
        │
        └── User clicks [Reject]
            Skip execution, feed rejection to LLM
            LLM continues: "Understood, I won't modify the note..."
```

## Context

The Vercel AI SDK (already a dependency) supports tool calling via `streamText({ tools, maxSteps })`. AI SDK 6 introduced `ToolLoopAgent` which handles the complete execution loop. However, because Obsidian plugins run in a browser-like environment and need granular UI control (approval cards), a manual loop using `streamText` with `maxSteps` is more appropriate than the higher-level `ToolLoopAgent` abstraction.

Key SDK references:
- `streamText` with `tools`: https://ai-sdk.dev/docs/ai-sdk-core/tools-and-tool-calling
- `maxSteps` (formerly `maxToolRoundtrips`): limits auto-execution rounds
- `tool` helper: defines Zod schema + execute function

## Notes

- **arxivite does NOT have this feature** — its "tool registry" is imperative intent routing (app decides which function to run), not LLM-native tool calling.
- **Provider support**: OpenAI, Anthropic, Google Gemini, and DeepSeek all support tool calling. Ollama support varies by model (Llama 3.1+, Qwen 2.5+ work well).
- **Bundle impact**: Minimal — `zod` is the only new runtime dependency (~15KB gzipped), and it's already commonly used with Vercel AI SDK.
- **Alternative considered**: XML tag parsing (`<edit-note>...</edit-note>`) is simpler (~4–6 hours) but less robust. Tool calling is the correct long-term architecture.
