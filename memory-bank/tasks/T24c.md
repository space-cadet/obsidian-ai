## Problem

Chat session state is currently owned in several places: each React view keeps
its own session arrays, storage tracks transcript hydration separately, and
session actions, message actions, agent callbacks, persistence, and sync can
independently update or save snapshots. This allows a completed disk read to
mark storage hydrated even when a cancelled view callback drops the messages.
It also creates possible stale-operation races around tab switches, deletion,
and sync snapshots.

The latest PR #12 Codex review reported the hydration/readiness race as a P1.
Other races found during source review are architectural risks and are not
claimed as device-reproduced failures.

## Objective

Establish one small plugin-owned owner for persistent chat-session state and
route session loading, message and metadata changes, deletion, sync application,
and durable flushing through explicit operations.

## Scope

- Keep transcript readiness with the messages installed in the shared state.
- Pin async send, edit, and retry work to the session ID captured at start.
- Reject stale reads or sync results after newer edits or deletion.
- Keep metadata-only updates lazy; message changes require a complete current
  transcript, while intentional edit/retry truncation remains valid.
- Migrate all persistent session mutation paths to the shared owner and remove
  duplicate hydration, deletion, and raw session-array mutation paths.
- Flush pending writes during plugin shutdown.
- Reuse the existing JSONL/index format, `ChatStorage` transaction and recovery
  code, and sync engine. Do not add a parallel permanent store or a new generic
  state-management framework.

## Acceptance Criteria

- [ ] One plugin-owned state owner serves every Chat Lab view using the same
  plugin instance.
- [ ] Hydration readiness and the installed message payload change together;
  sends and opens cannot proceed on storage bookkeeping alone.
- [ ] Metadata-only updates do not force transcript reads or overwrite
  transcript content.
- [ ] Async sends stay attached to their captured session ID through tab
  switches; stale reads and sync results cannot undo newer edits or resurrect
  deleted sessions.
- [ ] Explicit deletion remains authoritative until its durable write succeeds;
  omitted IDs in partial sync snapshots are not treated as deletions.
- [ ] Message operations use complete transcripts while allowing intentional
  edit/retry truncation.
- [ ] Persistent UI, context, agent, deletion, and sync mutation paths use the
  explicit owner API; no permanent raw `setSessions` bypass remains.
- [ ] Failed writes remain dirty and retryable; view unmount and plugin
  shutdown do not drop pending writes.
- [ ] Focused tests cover hydration/tab switch/send, two views, edit during
  hydration, delete during load/sync, send target pinning, metadata-only
  updates, intentional truncation, sync/local overlap, failed writes, and
  flush/unload behavior.
- [ ] TypeScript, production build, formatting, and diff checks pass; live
  Obsidian/device acceptance is recorded separately.

## Implementation Plan

1. Add a narrow plugin-owned session state owner initialized from the existing
   index-only `ChatStorage` load.
2. Expose explicit operations such as `ensureLoaded`, `updateMetadata`,
   `updateMessages`, `deleteSession`, `applySyncSnapshot`, and `flush`.
3. Connect React views through a subscription adapter; keep active-tab selection
   and purely visual state view-scoped.
4. Migrate session open, hydration, send, context/draft, edit/retry, agent
   callbacks, delete, and sync paths to the owner, capturing session IDs at
   operation start.
5. Remove the previous persistent mutation paths once all callers have moved.
6. Add focused race and lifecycle coverage at the owner/storage handoff.

These steps may land in reviewable commits, but the task is not complete while
old persistent mutation paths remain active.
