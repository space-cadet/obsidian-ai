# T63: Context Item Caching

## Status

**PENDING** — Priority: MEDIUM

## Description

Cache resolved context items to avoid re-reading vault files on every turn.

## Problem

`resolveContextItems()` in `ContextEngine.ts` re-reads all context files fresh on every `handleSend()`. For a context set with 5-10 notes, this means repeated file I/O and token estimation on every message.

## Proposed Solution

Session-scoped memoization:

- Cache key: `filePath + mtime + tokenBudget`
- Cache value: `{ contextString, wasTruncated, stats }`
- Invalidate when:
  - File mtime changes
  - Token budget changes
  - Context item list changes

## Implementation Notes

- Store cache in a WeakMap or simple Map in `useMessageActions` hook
- Clear cache on session change
- No persistent storage needed — session-scoped is sufficient

## Acceptance Criteria

- [ ] Context items cached per session
- [ ] Cache invalidated on file change (mtime check)
- [ ] Cache invalidated on budget/settings change
- [ ] Measurable reduction in repeated `resolveContextItems` calls

## Session-Isolation Defect — 2026-09-10

The diagnostic screenshots exposed context items leaking from older chats into
new sessions. `useContextItems` synchronizes from `activeSessionIdRef.current`
without depending on the actual session ID, so the persistence effect can write
the stale list into the new session. New sessions are created with empty
context items; this is a hook synchronization bug, not intentional inheritance.

Follow-up: depend on the active session ID, reset context state defensively when
creating a chat, and add two-session isolation tests. Keep this separate from
the still-pending session-scoped cache invalidation work above.
