# T37: Idempotent Bulk Note Creation and Batch Scope Decision
*Created: 2026-08-05*
*Completed: 2026-08-05*

**Status:** ✅ **COMPLETED**
**Priority:** HIGH

## Problem

An approved `create_notes` batch could create several new notes and then encounter
an already-existing target. The tool returned an error despite the partial
success, which made a safe, common rerun look like a failed operation.

## Implemented Contract

- `create_notes` validates forbidden paths and duplicate requested paths before
  it writes anything; these invalid plans remain terminal no-write errors.
- Existing target paths are idempotent skips. The tool creates every other
  requested missing note, never overwrites content, and reports the created and
  skipped paths.
- If another actor creates a target between the check and the write, that race
  is also reported as a safe skip. Other unexpected vault failures preserve the
  created/skipped partial-result details in the error.
- The pending approval and completed tool card both explain this behavior, so a
  user can distinguish a true error from an expected pre-existing note.

## Batch Scope Decision

No generic “batch any tool” feature was added. Creation is naturally
idempotent and the results are easy to report. Other mutations need their own
safety design: a `move_notes` candidate needs collision preflight; a structured
multi-note patch needs a per-file preview and expected-content checks; edits,
appends, and deletes should not be batched until they have an explicit
preview-to-approve-to-apply and partial-result contract.
