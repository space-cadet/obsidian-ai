## Description

Make sync state belong to the correct vault, server, account, remote path, and encryption setup. Make failed work visible and retryable.

## Acceptance Criteria

- [ ] A change to sync identity invalidates old cache and index state.
- [ ] Failed items remain available for retry.
- [ ] Retry does not repeat successful items unnecessarily.
- [ ] Chat sessions and each plugin-data category report separate results.
- [ ] The user can tell whether a sync was complete, partial, or failed.

## Implementation Details

The identity must include the vault, server, account, remote path, backend, and encryption identity. Add a small durable retry record instead of relying only on the pending flag in IndexedDB.
