# T22 — ChatApp.tsx Component Decomposition
*Created: 2026-05-28 23:05 IST*
*Status: 🔄 IN PROGRESS*

## Problem Statement
`src/components/ChatApp.tsx` has grown to **1,948 lines / 63 KB**. It contains:
- 24+ `useState` declarations
- 10 `useRef`s
- 8+ `useEffect` hooks
- ~25 handler functions
- ~300 lines of JSX

This violates single-responsibility principle and makes the component unmaintainable.

## Root Cause
Every chat feature (sessions, streaming, context, group chat, tool approval, editing, export, zen mode, debate mode, auto-save, title generation) is crammed into one component. State, logic, and UI are not separated.

## Refactoring Plan

### Phase 0: Inline Utilities ✅ COMPLETE
Move standalone helper functions out of ChatApp.tsx into `src/lib/`.
- **Files created:**
  - `src/lib/systemPrompt.ts` — `buildSystemPrompt` (67 lines)
  - `src/lib/sessionTitle.ts` — `generateSessionTitle` + `generateSessionTitleLLM` (137 lines)
  - `src/lib/slashCommand.ts` — `SlashCommand`, `parseSlashCommand` (23 lines)
  - `src/lib/contextUtils.ts` — `contextItemKey`, `sameContextItems` (26 lines)
  - `src/lib/agentVisuals.ts` — `getAgentColor`, `getAgentIcon` (28 lines)
  - `src/lib/sessionUtils.ts` — `makeId`, `pruneSessions` (24 lines)
- **Result:** ChatApp.tsx 1,948 → 1,700 lines (-248)
- **Build:** ✅ Passes

## Risk
Medium. ChatApp is the heart of the plugin. Every feature touches it. Need careful extraction to avoid breaking state synchronization (especially `useEffect` chains and ref mirrors).

## Notes
- The `handleSend` function (~660 lines) is the most complex — it contains streaming logic, tool loops, group chat broadcasting, and error handling. Extracting this will require the most care.
- Ref mirrors (`messagesRef`, `sessionsRef`, etc.) exist to avoid stale closures in async callbacks. Any hook extraction must preserve this pattern or replace it with a better solution.
