## Description

Make Chat Lab's plugin-data sync safe for two-way use across devices. Define a clear boundary with SyncIt so SyncIt owns whole-vault sync while Chat Lab owns its plugin-specific data rules.

Chat Lab must not add whole-vault sync. The two plugins must not write the same remote paths through separate sync engines.

## Acceptance Criteria

- [ ] One safe sync path is defined for all selected Chat Lab data.
- [ ] Two-way changes, conflicts, recovery copies, and deletions have clear rules.
- [ ] Sync identity changes cannot reuse old cache state.
- [ ] Failed work can be retried and is reported by data category.
- [ ] A separate, versioned `dataSyncProvider` contract is documented for a future SyncIt integration.
- [ ] The two plugins have an acceptance test proving that they do not overlap unexpectedly.

## Implementation Details

The work is split into T57a–T57d:

- T57a: common encrypted and atomic plugin-file sync path.
- T57b: two-way shared state, conflicts, recovery, and deletion records.
- T57c: sync identity, retry, and separate failure reporting.
- T57d: SyncIt integration contract and overlap prevention.

The existing `integrationProvider` interface remains for AI tools. Sync support must use a separate contract and must not overload tool capabilities.
