# Task: T62 — Tool Payload Elision in History Replay
*Created: 2026-08-26 22:15:00 IST*
*Status: 🆕 PROPOSED*

## Objective
Reduce token burn in multi-turn tool conversations by eliding (summarizing)
tool call arguments and tool result content in history replay. The model sees
only that a tool was called and that it returned, not the full payloads from
prior turns.

## Motivation
obsidian-ai currently replays the **full Vercel AI SDK shape** for every tool
message in history:
- Assistant message with complete `tool-call` parts (full `args` JSON)
- Tool message with complete `tool-result` parts (full `output` text, up to
  `maxToolResultTokens`)

On a 10-turn conversation with 2 tool calls per turn, this multiplies
history size by ~2× and fills context with stale JSON that the model no
longer needs. OpenClaw handles this by rendering tool calls as:
```
tool call: read_note [input omitted]
tool result: abc-123 [content omitted]
```

## Acceptance Criteria
- [ ] Tool history mode setting: `"elide"` (default) or `"preserve"`
- [ ] In `elide` mode, `buildHistoryWithTools` replaces full payloads with
  minimal summaries:
  - Tool call: `{toolName} [input omitted]`
  - Tool result: `[{charCount} chars, elided]`
- [ ] In `preserve` mode, existing full-payload behavior retained (for debug)
- [ ] Setting exposed in Advanced Settings: "Tool History Verbosity"
- [ ] UI/export transcript remains untouched (only model-facing history changes)
- [ ] Token estimator updated to account for elided tool parts (~20 chars each)

## Implementation Notes

### Where to Change
`src/hooks/useMessageActions.ts` — `buildHistoryWithTools()`:

```typescript
// Current: full payload replay
assistantContent.push({
  type: "tool-call",
  toolCallId: part.call.toolCallId,
  toolName: part.call.toolName,
  input: part.call.args, // ← full JSON
});

// Proposed: elided replay (when settings.toolHistoryMode === "elide")
assistantContent.push({
  type: "tool-call",
  toolCallId: part.call.toolCallId,
  toolName: part.call.toolName,
  input: "[elided]",
});
```

### Token Impact
| Scenario | Full Replay | Elided | Savings |
|----------|-------------|--------|---------|
| 1 tool call, 2000-token result | ~2000 tokens | ~20 tokens | **99%** |
| 10-turn conv, 2 tools/turn | ~40k tokens | ~400 tokens | **99%** |

### Edge Cases
- **Immediate tool context:** The turn that *just* produced a tool result still
  needs the full result in the next request (the agent loop consumes it).
  Elision only applies to **history replay**, not the active turn's tool
  consumption.
- **OpenResponses loop:** Must ensure elision happens in the message
  projection, not in the persisted transcript.
