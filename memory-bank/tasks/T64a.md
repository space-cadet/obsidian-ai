## Description

Grid-search experiment across the full parameter space of context optimization
settings to identify Pareto-optimal configurations — those that maximize token
savings without sacrificing excessive conversation history.

A configuration is on the Pareto frontier if no other configuration achieves
both higher token savings AND more messages retained.

## Parameter Space

| Setting | Default | Test Values |
|---------|---------|-------------|
| `maxToolResultTokens` | 4000 | 0, 1000, 2000, 4000, 8000 |
| `toolHistoryMode` | "elide" | "elide", "preserve" |
| `maxContextMessages` | 10 | 5, 10, 20, 50, 100 |
| `maxRequestTokens` | 32000 | 8000, 16000, 32000, 64000 |
| `preserveRecentMessages` | 4 | 2, 4, 8 |
| `requestResponseReserveTokens` | 2048 | 1024, 2048, 4096 |

## Method

1. Generate all combinations (or Latin-hypercube sample for large space)
2. For each fixture (coding, research, attachment):
   a. Apply configuration
   b. Measure: tokens_before, tokens_after, savings_percent
   c. Measure: messages_kept, tool_calls_kept, recent_messages_intact
3. Identify non-dominated points per fixture
4. Report: frontier configs ranked by use case

## Output Format

Per-fixture table of frontier points:
```
Fixture: coding-session
| Config | Savings | Msgs Kept | Tools Kept | Frontier? |
| (elide, mtr=2000, mcm=20) | 67% | 20/30 | 8/15 | ✅ |
| (elide, mtr=4000, mcm=50) | 45% | 50/30 | 15/15 | ✅ |
| (preserve, mtr=8000, mcm=100) | 12% | 100/30 | 15/15 | ✅ |
```

## Acceptance Criteria

- [ ] Harness supports parameterized strategy factory (not hardcoded)
- [ ] Sweeps at least 3 dimensions: `maxToolResultTokens`, `toolHistoryMode`, `maxContextMessages`
- [ ] Reports Pareto frontier per fixture
- [ ] Recommends best config per use case (coding vs research vs attachment)
- [ ] Runs in <30 seconds for full sweep (Level 1, no API calls)
