## Description

Add an opt-in, anonymized telemetry system that collects usage statistics from
plugin installations. The goal is to understand which features are used, which
providers are popular, and where users encounter issues — all without collecting
any personally identifiable information or sensitive data.

**Critical:** This must be strictly opt-in with full disclosure. No dark patterns,
no nagging, no data collection without explicit consent.

## Acceptance Criteria

- [ ] Telemetry is disabled by default (opt-in, not opt-out)
- [ ] First-run dialog asks user to enable telemetry with clear explanation
- [ ] Settings page has a toggle with detailed description of what is/isn't collected
- [ ] Data collected is strictly anonymized (random UUID, no IP, no content)
- [ ] What IS collected: provider type, feature usage counts, token ranges (not exact counts), error types
- [ ] What is NOT collected: message content, API keys, file names, vault structure, IP addresses
- [ ] Data is sent to a backend endpoint (to be determined)
- [ ] Users can disable telemetry at any time via settings
- [ ] Users can delete their anonymized data (via UUID-based lookup)

## Implementation Details

### Data Collection Boundary

**Collected (anonymized):**
```typescript
interface TelemetryEvent {
  id: string;           // random UUID, stable per installation
  version: string;      // plugin version
  timestamp: number;    // event time
  event: string;        // event type: "chat_started", "tool_used", "error", etc.
  provider?: string;    // "deepseek", "openai", etc.
  feature?: string;     // "group_chat", "agent_tools", "streaming", etc.
  value?: number;       // numeric metric (e.g., conversation length in turns)
  errorType?: string;   // "rate_limit", "network", "timeout", etc.
}
```

**NOT collected:**
- Message content, prompts, responses
- API keys, tokens, credentials
- File names, paths, vault structure
- User identity, IP address, location
- Obsidian vault metadata

### Backend

Options:
1. Self-hosted endpoint on user's VPS (quantumofgravity.com)
2. Third-party telemetry service (PostHog, Plausible, etc.)
3. Simple cloud function (Cloudflare Workers, Vercel Edge)

Requirements:
- Accept POST with JSON payload
- Store in database (SQLite/PostgreSQL)
- Provide deletion endpoint by UUID
- GDPR/privacy compliant
