## Description

Quantifies the T62a regression: how much of original tool result content
actually survives when `toolHistoryMode` is set to "preserve" at various
`maxToolResultTokens` thresholds.

**The bug:** Even in "preserve" mode, `truncateTextForTokens()` in
`buildHistoryWithTools()` still slices tool results to `maxToolResultTokens`
(default 4000). So "preserve" does not actually preserve full content — it
merely preserves *more* than "elide" mode.

This experiment measures exactly how much is lost at each threshold.

## Method

1. For each fixture, extract total original tool result text (sum of all
   `part.result.content` across all tool calls)
2. For each `maxToolResultTokens` in [0, 1000, 2000, 4000, 8000, 16000, ∞]:
   a. Run `buildHistoryWithTools(fixture.messages, maxMsg, mtr, "preserve")`
   b. Extract all tool-result output text from the generated history
   c. Compare: retained_chars / original_chars = retention_percent
3. Plot retention curve per fixture

## Key Question

At the default `maxToolResultTokens=4000`, does "preserve" mode retain:
- 95%+ of content (minor truncation)?
- 50% of content (significant loss)?
- 5% of content (basically broken)?

The answer determines whether T62a's fix should be:
- (a) Only apply `maxToolResultTokens` in "elide" mode, OR
- (b) Raise the default threshold, OR
- (c) Make it independently configurable

## Results: Grammar Migration Fixture (2026-08-27)

**Fixture**: Real session JSON, 26 messages (13 user + 13 assistant turns), loaded as `benchmarks/fixtures/grammar-migration-13-turns.json`.

**Key Finding**: `maxContextMessages: 10` reduces total token exposure by **~42%** for this workload.

| MsgCap | Mode | ToolTok | Total Tokens | Peak/Turn | Dropped |
|--------|------|---------|-------------|-----------|---------|
| ∞ | preserve | 64000 | 146,747 | 23,450 | 0 |
| 10 | preserve | 64000 | 85,110 | 11,217 | 72 |
| 10 | preserve | 4000 | 76,510 | 10,708 | 72 |
| ∞ | preserve | 4000 | 129,547 | 21,730 | 0 |
| 10 | elide | 4000 | 6,868 | 803 | 72 |

**Observations**:
1. **The 10-message cap is the dominant factor** — cuts total tokens by ~42% regardless of tool mode.
2. **`maxToolResultTokens` matters only in preserve mode** — at 64000 vs 4000, difference is ~11% (85K vs 76K with cap=10). The T64a bug (preserve still truncates) is real but impact is small at high thresholds.
3. **`elide` mode is extremely aggressive** — 6,868 tokens total vs 85K for preserve. This confirms T62a's severity: elide breaks multi-turn workflows by design.
4. **Attachment fixture shows same pattern** — 86K unlimited → 74K with cap=10 (~14% reduction). Less dramatic because attachment session has fewer total turns.

**Caveat**: Harness uses tiktoken (GPT-4 tokenizer). Gemma 4-31b tokenizer will produce different absolute numbers but similar relative ratios.

**For T62a Decision**: The data supports Option 2 (Agent-Mode Auto-Preserve) or Option 6 (Hybrid — elide old, preserve recent). With cap=10, even preserve mode stays bounded (~85K total), so the token "cost" of preserve is acceptable when the message window is active.
