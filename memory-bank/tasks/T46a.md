## Problem Statement

`src/hooks/useMessageActions.ts` is approximately 1,533 lines and combines
React state handling with request assembly, context construction, semantic
compaction, history budgeting, protocol selection, streaming, persistence,
tool execution, and approval handling. The hook is past the reconsideration
threshold recorded by T22 and is now a request-lifecycle module in practice.

## Objective

Move the non-UI lifecycle of one chat turn into a testable coordinator while
leaving the React hook as a thin state and command adapter.

## Scope

- Build the model request from the resolved context and model history.
- Select and run the native or OpenResponses protocol path.
- Coordinate streaming events, tool calls, approvals, continuation, and stop.
- Persist the final message and report lifecycle state back to the UI.
- Reuse the T60 capability resolution and T48/T62 history policy rather than
  creating new parallel rules.

## Acceptance Criteria

- [ ] `useMessageActions.ts` no longer owns the complete request lifecycle.
- [x] The extracted coordinator can be tested without mounting React.
- [ ] Native and OpenResponses paths share callback and persistence policy.
- [ ] Tool approval and continuation preserve the existing result contract.
- [ ] Context construction and model-history policy remain delegated to their
      owning modules.
- [x] Existing hook tests, agent-loop tests, TypeScript, and production build
      pass after each extraction slice.
- [ ] The original hook remains a small composition layer with compatible
      behavior and imports.

## Non-Goals

- Redesigning T60 capability semantics.
- Choosing the T62a elision strategy; T64b supplies evidence for that choice.
- Decomposing `ChatApp.tsx`; T22 is complete.
- Splitting sync modules; that remains a conditional T57 follow-up.

## Implementation Progress — 2026-08-27

`src/agent/ChatTurnCoordinator.ts` now provides a React-free `runChatTurn`
entry point. It selects the native or OpenResponses loop, passes the same
approval and result callbacks to either path, and gives OpenResponses the same
resolved tool definitions used by the native path.

The hook uses this coordinator for the main turn path, but it still prepares
context and history, assembles the request, persists messages, and owns UI
approval state. The next slice must move those responsibilities behind clear
inputs and outputs without changing the T48/T62 history rules.

The current implementation is on `feat/t46-architecture-decomposition`, based
on `a15c47646e1141239b269c8f608331889b1b32df`.

The request-preparation slice is now implemented in
`src/agent/ChatTurnRequest.ts`. It builds the prompt, bounded history, budgeted
messages, and attachment content without React. The hook remains responsible
for UI callbacks, streaming display, approval state, and final persistence.
