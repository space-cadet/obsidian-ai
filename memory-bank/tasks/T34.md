## Description
Fix the tabbed chat interface so every open chat tab owns its own live generation process state. The current implementation stores streaming text, tool approval state, abort controller, and token counters once per `ChatApp`, so a response started in one tab can appear in another tab after switching tabs. This task keeps the shared toolbar/composer contract while isolating runtime state by `sessionId`.

## Problem Statement
Saved messages are session-scoped, but active generation state is panel-scoped:

- `ChatApp` has one `isStreaming`, `currentAiMessage`, `currentContentParts`, `pendingToolCall`, `controllerRef`, and `runningTokenTotal`.
- `ChatMessages` renders the streaming bubble whenever those global fields are set, regardless of the active session.
- `useMessageActions` captures the send session for final message persistence, but stream deltas and tool state are pushed through shared setters.
- `ToolExecutor` receives `() => activeSessionIdRef.current`, so tool context can drift if the user switches tabs during a tool-using response.

## Acceptance Criteria
- [x] Starting a response in tab A and switching to tab B does not show tab A's streaming bubble, typing indicator, pending tool card, or token increments in tab B.
- [x] Tab A continues streaming in the background and shows its live response when reselected.
- [x] Stop aborts only the active tab's generation unless an explicit future "stop all" command is added.
- [x] Sending in tab B while tab A is streaming is supported with independent controllers; no reply text crosses tabs.
- [x] Tool approval cards and resolver callbacks are tied to the originating session, not the currently active tab at approval time.
- [x] `search_past_sessions` and other tool calls use the originating session ID for active-session exclusion and context.
- [x] Retry, edit, slash-command, attachment, group-chat, OpenResponses, and standard streaming paths preserve their existing behavior within the originating session.
- [x] Regression tests cover cross-tab streaming display isolation and tool-session identity drift.
- [x] `pnpm test`, `pnpm run build`, and `git diff --check` pass before closing.

## Implementation Details
Introduce a per-session runtime state map in `ChatApp` or a focused hook such as `useChatRuntimeState`.

Each `sessionId` should have a runtime entry containing:

- `isStreaming`
- `currentAiMessage`
- `currentContentParts`
- `pendingToolCall`
- `controller`
- `resolveTool`
- `runningTokenTotal`
- optional typing agents and group-chat runtime metadata

`ChatApp` should derive the visible runtime from `activeSessionId` and pass only that runtime to `ChatMessages`, `PendingToolCard`, and `ChatInput`. `useMessageActions` should capture `originSessionId` at send time and update runtime through session-keyed helpers. Tool executors and approval handlers should receive that captured session ID rather than reading `activeSessionIdRef.current`.
