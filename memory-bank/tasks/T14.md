## Paired OpenClaw Gateway Chat Client — 2026-09-26

The user wants Obsidian to act as a chat frontend for a running OpenClaw
instance, like Telegram. In this mode the Gateway owns model execution and tool
execution; the plugin does not relay Gateway tool calls into its local vault
tool executor. Support both desktop and mobile by pairing each device directly
with the Gateway. Persist device identity and pairing credentials locally and
do not include private keys or device tokens in plugin sync or exports. This is
a separate transport from the existing HTTP OpenResponses path and must be
designed and accepted as such.

Open decisions: Gateway discovery/address entry, pair approval and revocation,
reconnect/session behavior, streamed event mapping, and any host-side approval
UX the plugin needs to display. Existing OpenResponses local-tool behavior
remains a separate mode.
