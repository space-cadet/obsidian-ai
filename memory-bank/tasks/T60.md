## Description
Replace the duplicated, transport-specific tool wiring with one canonical
capability registry and a shared validated execution pipeline. Preserve the
separate ownership of approval/audit policy (T38), provider integrations
(T39), orchestration decomposition (T46), advanced vault tools (T17), and
compaction retrieval (T48c).

## Acceptance Criteria
- [ ] One canonical definition owns schema, description, risk, availability,
  handler, preview, formatting, audit redaction, and concurrency metadata.
- [ ] AI SDK, OpenResponses, prompt summaries, approval cards, and dispatch are
  derived from the resolved registry.
- [ ] Every transport validates and executes calls through one fail-closed
  pipeline with structured errors and cancellation.
- [ ] Direct chat, remote-agent, and council flows preserve all calls and
  matching results.
- [ ] Contract tests cover registry, transport, policy, execution, rendering,
  persistence, and unavailable-capability behavior.

## Implementation Details
The target pipeline is: resolve, validate, authorize, preflight, approve,
execute, validate result, audit, model-render, and persist the full result.
Reads may use bounded concurrency; mutations are serialized by target and use
optimistic concurrency where existing content can change.
