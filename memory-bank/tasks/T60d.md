# Task: T60d — Token-Efficient Search Defaults

## Problem

The 500k-token incident (2026-08-25) revealed that `search_notes` returns up
to 100 matches with full metadata (path, basename, modified, created, size).
Each result set is ~3,000 tokens. When the model makes 17 sequential calls,
the accumulated results alone contribute ~51k tokens — even before the
protocol duplication bug (`T60b`) is accounted for.

## Proposed Changes

1. **Lower `search_notes` default limit:** 100 → 20 (max 50)
   - Most lookups need only the top matches
   - User can still request more via the `limit` parameter

2. **Add batch guidance to system prompts**
   - Teach the model to use `search_note_content` for multi-term lookups
   - Example: "卫生间 厨房 冰箱" in one call instead of 3 separate `search_notes`

3. **Trim match metadata on large arrays**
   - For result sets >20 matches, omit `created`/`size` to reduce token load
   - Keep `path`, `basename`, `modified` as essential
