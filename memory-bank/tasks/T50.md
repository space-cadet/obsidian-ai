## Description

Add support for OpenAI's stateful APIs: Responses API (with `previous_response_id`)
and potentially Threads API. These APIs maintain conversation state server-side,
meaning the client sends only the new message per turn rather than the full
conversation history. This dramatically reduces token usage for long conversations.

**Important:** DeepSeek's Responses API implementation is stateless (confirmed via
their compatibility docs: `previous_response_id` is "Not supported"). This feature
is primarily for OpenAI users.

## Acceptance Criteria

- [ ] Plugin can use OpenAI Responses API as an alternative to Chat Completions
- [ ] When using Responses API, only the new user message is sent per turn
- [ ] `previous_response_id` is stored and passed correctly between turns
- [ ] Tool calling works correctly with Responses API format
- [ ] Streaming works correctly with Responses API SSE events
- [ ] Falls back gracefully to Chat Completions if Responses API is unavailable
- [ ] Settings toggle to choose between "Chat Completions" and "Responses API"
- [ ] Cost comparison shown in settings (estimates based on typical usage patterns)

## Implementation Details

### Architecture

The Vercel AI SDK has different functions for these APIs:
- Chat Completions: `streamText()` / `generateText()`
- Responses API: `streamObject()` with Responses-specific options

A provider abstraction layer is needed:
```typescript
interface ChatProvider {
  sendMessage(message: string, options: ProviderOptions): AsyncGenerator<StreamEvent>;
  // For stateful providers, stores response_id internally
  // For stateless providers, manages messages[] array
}
```

### OpenAI-Specific

```typescript
import { openai } from '@ai-sdk/openai';

const response = await openai.responses.create({
  model: 'gpt-5',
  input: "What's the weather?",
  previous_response_id: lastResponseId, // null for first message
});
```

### Provider Compatibility Matrix

| Provider | Stateful | API | Notes |
|---|---|---|---|
| OpenAI | ✅ | Responses API | Full `previous_response_id` support |
| DeepSeek | ❌ | Responses API (format only) | Stateless — sends full history each time |
| Anthropic | ❌ | Messages API | Stateless — sends full history each time |
| Gemini | ⚠️ | Sessions API | Different API shape, not standard |
