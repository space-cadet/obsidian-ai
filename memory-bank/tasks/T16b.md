## Description
Allow users and agents to address participants explicitly using stable agent
handles such as `@gemini`, while preserving `@` context attachment for notes,
folders, and tags.

## Acceptance Criteria
- [ ] Each agent has a validated stable participant ID distinct from `profileId`.
- [ ] Aliases resolve to agent IDs without ambiguity.
- [ ] A unified resolver separates agent targets, context references, unknown mentions, and clean text.
- [ ] Unknown `@tokens` remain ordinary text and do not alter routing.
- [ ] Messages preserve structured source and target participant IDs.
- [ ] Autocomplete distinguishes agent mentions from vault context items.

## Implementation Details
Use stable IDs internally and display names only for presentation. Namespace
agent and human IDs separately. Store resolved targets in message metadata rather
than relying on reparsing text during replay or agent-to-agent dispatch.
