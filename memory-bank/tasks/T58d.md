## Description

Resolve the post-delivery sync-panel issues found during tablet review and
source audit. Unify planning, dry-run, real-sync, plugin-data, and index-rebuild
progress so the user can see what is being scanned, planned, transferred, or
reconciled.

This task records the approved plan; implementation has not started.

## Acceptance Criteria

- [ ] Planning stages show visible progress before item transfers begin.
- [ ] Dry-run planning includes selected plugin-data components without writing
      local, remote, or index state.
- [ ] Plugin-data state remains distinct from the chat-session SyncIndex and
      is shown separately in the plan and result.
- [ ] One stable UI row represents each operation and transitions through
      pending, active, done, skipped, or error without duplicates.
- [ ] The shimmer is shown only on the latest active operation.
- [ ] The progress bar remains visible at 100% after completion and shows a
      final summary until the next run or dismissal.
- [ ] Index rebuild shows planning progress, total work, completed work,
      cancellation, and a final result.
- [ ] Rebuild avoids repeated local/remote scans and uses bounded concurrency
      for independent transfers.
- [ ] Conflicts produce partial/attention-required status rather than
      reporting complete.
- [ ] Focused tests cover dry-run plugin-data planning, progress transitions,
      rebuild progress, duplicate prevention, and conflict status.

## Implementation Details

Use a shared progress event contract with explicit phases and stable operation
identifiers. The initial planning event may be indeterminate until the plan
total is known; subsequent events report completed and total.

The chat-session index remains session-only. Plugin files use their separate
identity-scoped shared state. A dry run reads and compares both state models
but does not mutate either one.

Rebuild should reuse the computed plan, replace repeated membership scans with
maps or sets, and apply the existing bounded concurrency helper where safe.
The UI should retain the final 100% state after the operation settles.
