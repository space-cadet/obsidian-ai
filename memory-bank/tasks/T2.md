## Description

Replace the current single-turn `callApi()` pattern with a stateful multi-turn conversation chain. Full message history is built and sent to the LLM on every turn. Conversations are persisted to disk and can be loaded in future sessions.

## Data Model

```typescript
interface ChatMessage {
  id: string
  role: "user" | "assistant" | "system"
  content: string
  timestamp: number
  contextRefs?: string[]
}

interface Conversation {
  id: string
  title: string
  createdAt: number
  updatedAt: number
  messages: ChatMessage[]
}
```

## Context

The `MessageQueue` in the current codebase is UI-only (arrow key navigation of past prompts). It is not replaced — it stays in the inline tooltip. The `ConversationManager` is a new separate concern for the chat panel only. The full LangChain message array (all turns) is passed to `streamChat()` on every submit, giving the LLM complete conversation context.
