## Description

Complete the on-demand, read-only health-check experience for Chat Lab plugin
files, session indexes and transcripts, and memory stores. This task also
records the user-approved, backed-up manual recovery of the findings in the
October 19 report. Productized repair controls remain out of scope; prevention
of new persistence inconsistencies is tracked under T24b.

## Acceptance Criteria

- [x] The health check remains read-only, bounded in scan size, and exports
  findings without transcript content.
- [x] Long findings lists appear in a bounded, scrollable Settings container.
- [ ] (Out of current scope) Repairs require an explicit preview and show the
  affected records and files before applying changes.
- [ ] (Out of current scope) Every repair backs up files before writing and
  reports success or failure.
- [ ] (Repair work is out of current scope) Duplicate message IDs are resolved only when the records can be safely
  identified; conflicting content is preserved for review.
- [ ] (Repair work is out of current scope) Unindexed transcripts receive an explicit, safe disposition. Do not
  silently index, overwrite, or delete ambiguous files.
- [ ] (Repair tests are out of current scope) Tests cover duplicate IDs,
  message-count mismatches, unindexed transcripts, backup creation, and failed
  repair writes.
- [x] Mobile plugin-load and Settings acceptance are recorded separately from
  build and automated-test results.
