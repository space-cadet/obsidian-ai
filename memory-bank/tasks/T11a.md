## Description

Complete the on-demand, read-only health check and provide a reviewed repair
flow for chat data findings. The task also records the user-approved,
backed-up manual recovery of the October 19 report. T24b separately tracks
prevention of new persistence inconsistencies.

## Acceptance Criteria

- [x] The health check remains read-only, bounded in scan size, and exports
  findings without transcript content.
- [x] Long findings lists appear in a bounded, scrollable Settings container.
- [x] Repair previews list proposed file changes and give reasons for skipped
  files; users select unindexed chats individually.
- [x] Repairs revalidate the preview, back up and verify originals, verify
  writes, and report success, failure, or interrupted recovery.
- [x] Only byte-identical duplicate records with the same ID are removed;
  conflicting records and ambiguous counts remain unchanged.
- [x] Unindexed recovery requires valid messages and timestamps; empty,
  malformed, unsafe, conflicting, or otherwise ambiguous transcripts remain
  unchanged for review.
- [ ] Targeted tests cover duplicate handling, count reconciliation, recovery,
  backup verification, and failed or interrupted writes.
- [ ] Post-reload Android acceptance of the final repair modal and Settings
  shortcut styling is recorded separately from build and install evidence.
