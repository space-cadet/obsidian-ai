## Description

Add the ability to export and import plugin settings as JSON files. The plugin
has accumulated a large number of settings (provider profiles, remote storage
configs, tool policies, telemetry preferences, etc.) and users need a way to:

1. Back up their configuration
2. Migrate settings between devices
3. Share configurations with others (sanitized)
4. Recover from data loss

## Acceptance Criteria

- [ ] Settings can be exported to a JSON file via a button in the settings panel
- [ ] Settings can be imported from a JSON file via a button in the settings panel
- [ ] Import validates the JSON schema and rejects invalid/malformed files
- [ ] API keys are redacted (replaced with `"REDACTED"`) in exports by default
- [ ] Optional: allow full export with API keys (with explicit confirmation warning)
- [ ] Import gracefully handles schema version mismatches (migration path)
- [ ] Import does not overwrite existing settings without confirmation
- [ ] Works with the current settings structure post-T23 decomposition

## Implementation Details

### Export Flow

1. User clicks "Export Settings" in settings panel
2. Plugin serializes `plugin.settings` to JSON
3. Redact sensitive fields: `apiKey`, `authToken`, `passphrase`
4. Add metadata: `exportedAt`, `version`, `schemaVersion`
5. Trigger browser download of `.json` file

### Import Flow

1. User clicks "Import Settings"
2. File picker opens, user selects `.json` file
3. Validate JSON structure against schema
4. Check `schemaVersion` — run migration if needed
5. Show diff/preview of what will change
6. User confirms → merge into existing settings
7. User cancels → no changes

### Schema Versioning

```typescript
interface ExportedSettings {
  schemaVersion: 1;
  exportedAt: string;
  version: string; // plugin version at export time
  settings: ObsidianAISettings; // current settings type
}
```

Migration rules for schemaVersion bumps:
- v1 → v2: rename field X to Y, add default for new field Z
- Migrations are applied sequentially: v1 → v2 → v3
