## Objective

Allow users to selectively choose which categories of plugin data participate in remote sync and export/import operations. Replace the all-or-nothing approach with fine-grained control over 7 data components.

## Background

T43c extended sync to all plugin data (settings, memory, persona, audit logs), but it was unconditional — everything synced. T49 added export/import, also unconditional. Users need control over what travels to remote storage, both for bandwidth/privacy and for practical workflow reasons (e.g., don't sync audit logs to a second device).

## Acceptance Criteria

- [x] `SyncComponentConfig` interface with 7 boolean toggles in settings
- [x] New "Sync Components" settings section between Multi-User Sync and Remote Storage
- [x] Export/import respects toggles (filters serialized data)
- [x] Remote sync respects toggles:
  - `_serializePluginData()` conditionally includes components
  - `_deserializePluginData()` only merges enabled components
  - `_syncTextFile()` helper for individual file sync (memory.json, persona.md, audit.jsonl)
  - Usage stats computed on upload, skipped on download
- [x] API keys excluded by default (security)
- [x] Backward compatible: defaults sensible, old data ignored if component disabled

## Data Components

| Component | File/Key | Default | Rationale |
|-----------|----------|---------|-----------|
| Chat sessions | `sessions/` | ✅ true | Core feature |
| Plugin settings | `plugin-data.json` | ✅ true | Preferences, prompts |
| API keys | inside plugin-data.json | ❌ false | Security — opt-in only |
| AI Memory | `memory.json` | ✅ true | Cross-device continuity |
| Memory audit log | `memory-audit.jsonl` | ❌ false | Large, device-local history |
| AI Persona | `persona.md` | ✅ true | User identity |
| Usage stats | computed | ❌ false | Upload-only, computed aggregate |

## Architecture

### Settings Layer

```typescript
interface SyncComponentConfig {
    chatSessions: boolean;
    pluginSettings: boolean;
    apiKeys: boolean;
    aiMemory: boolean;
    memoryAuditLog: boolean;
    aiPersona: boolean;
    usageStats: boolean;
}
```

Added to `ObsidianAISettings` as `syncComponents: SyncComponentConfig`.

Default values set in `DEFAULT_SETTINGS`.

### UI Layer

New file: `src/settings-sections/syncComponents.ts`

- Section title: "Sync Components"
- 7 checkboxes with descriptions
- Placed in settings nav between "Multi-User Sync" and "Remote Storage"
- Grouped visually: Core (sessions, settings), Identity (memory, persona), Advanced (audit, stats, keys)

### Export/Import Layer

Modified: `src/settings-sections/exportImport.ts`

- `serializeSettings()` now accepts `SyncComponentConfig` and filters before writing
- Redaction logic extended to respect `apiKeys` toggle
- Import merge skips disabled components

### Remote Sync Layer

Modified: `src/main.ts`

- `_serializePluginData()` reads `syncComponents` from settings, includes only enabled components
- API keys stripped unless `apiKeys: true`
- `_deserializePluginData()` merges only components that are enabled locally
- Credential fields (`apiKey`, `passphrase`, `password`) never overwritten from remote
- `_syncTextFile()` helper: uploads/downloads individual files (memory.json, persona.md, audit.jsonl) based on toggles
- Usage stats: computed fresh on upload, skipped entirely on download

## Notes

### Usage Stats Design
Usage stats are not stored as a file — they are computed on-demand from session data during upload. This avoids stale stats and ensures privacy (remote never sees raw conversation content, only aggregates).

### Security Boundary
Chat-session payloads use `EncryptionLayer` when a passphrase is set. The current auxiliary files (`plugin-data.json`, memory, persona, audit, and usage data) are written through the text-file path and still need the same encryption and integrity checks. Do not describe all remote data as encrypted until that work is complete.

### Current Limits

- Component toggles select which files participate, but they do not yet provide a separate conflict choice for each file.
- Downloaded memory, persona, and audit files can replace local files without a full comparison screen.
- API-key syncing remains disabled by default and local credentials are preserved during merges.
