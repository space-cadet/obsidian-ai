## Context
The original design doc envisioned a structured `DebugLogService` with ring buffer, redaction, and source-tagged events (`provider`, `models`, `chat`, etc.). The actual implementation prioritised **crash debugging** for T13 stability:
- Plain-text file logger instead of structured JSON events
- Console interception instead of explicit `debugLog.add(event)` calls
- No redaction yet — full prompts and note contents may appear in logs
- No bounded retention beyond 5MB file size limit

This is a pragmatic v1 that solves the immediate need (capture renderer crash data). The structured service can be layered on top later.
