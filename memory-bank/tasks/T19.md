## Description

Enable users to attach vault files (markdown notes, images, PDFs) to chat messages so the LLM can consume their content — not just reference them. Images are sent as base64 via Vercel AI SDK `ImagePart`. PDFs are sent as `FilePart` (Gemini) or extracted text (other providers). Markdown files are inlined as text.

## Architecture

### Attachment Data Flow
```
User selects file in ChatInput:
        │
        ▼
[ChatInput] → attachment chips UI
        │
        ▼
[ChatApp.handleSend()] → resolve attachments
        │
        ├── Markdown → read via vault.read() → TextPart
        ├── Image → read as base64 → resize → ImagePart
        └── PDF → FilePart (Gemini) or extract text → TextPart
        │
        ▼
[api.ts] → convert to provider-specific format
        │
        ▼
streamChat() / streamChatWithTools() → LLM
```

### AttachmentEngine (Planned)
```typescript
interface Attachment {
  type: "markdown" | "image" | "pdf";
  path: string;
  name: string;
}

class AttachmentEngine {
  resolveAttachment(att: Attachment, app: App): Promise<ContentPart>;
  // Markdown → TextPart
  // Image → ImagePart (base64, resized)
  // PDF → FilePart (Gemini) or TextPart (extracted)
}
```

## Design Decisions

1. **MVP scope**: Markdown (inline text), Images (base64 `ImagePart`), PDFs (`FilePart` for Gemini, text/skip for others)
2. **No external dependencies for MVP**: PDF text extraction deferred; image resizing via canvas
3. **Image size cap**: 1024px max dimension before base64 to avoid massive payloads
4. **Attachment resolution**: Centralized in `AttachmentEngine.ts`, not scattered across components
5. **Provider fallback**: If provider doesn't support a content type, skip with warning rather than fail

## Implementation Notes

- Vercel AI SDK `FilePart` for PDFs works with Gemini but may fail if system prompt contains file metadata. Keep file metadata in user message only.
- OpenAI/Anthropic do NOT support native PDF via chat completions. Must extract text or use Assistants API (out of scope).
- Current `handleSend()` in `ChatApp.tsx` is ~300+ lines. Adding attachment resolution will make it longer; consider extracting message-building logic.
- Group chat: all participants should see the same attachments. Orchestrator needs to include attachments in the prompt for each agent.
