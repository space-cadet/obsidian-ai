## Description

Prototype tags for saved chat sessions. Users can apply and remove tags in Chat
History and filter sessions by tag. An optional setting can suggest tags for
new sessions with a provider profile and model selected from configured AI
profiles. Agent tools manage tags on individual saved sessions, and users can
request suggestions for the active session from the main chat overflow menu.
Settings can generate tags sequentially for untagged saved sessions using the
selected provider/model and the same bounded excerpt. The user authorized this
data transfer on 2026-10-23.

## Implementation Details

See [session-tags.md](../implementation-details/session-tags.md) for the
end-to-end implementation reference, including storage, normalization,
provider request bounds, automatic/manual/bulk generation, agent tools, UI
behavior, sync boundary, and open acceptance.

- `ChatSession.tags` stores normalized labels; the JSONL session index persists
  these without loading message files. `autoTagPending` is set only on new
  sessions created while the setting is enabled.
- The Settings control is opt-in and lists configured provider profiles with
  their selected models. The dropdown uses compact profile names and displays
  the provider/model in the setting description. Tag generation uses the
  existing `ChatApiManager`.
- A bounded excerpt of up to eight user/assistant messages, with each message
  capped at 600 characters, is sent to the selected provider. The setting
  explains this data flow. Failures are logged and do not interrupt chat.
- An in-flight set scoped to the shared session owner prevents duplicate
  suggestion requests across open chat panes.
- Chat History uses a compact searchable list, an in-app tag filter with
  per-tag session counts and keyboard selection. Session rows preview the
  first four tags as chips, show a `+N` marker for additional tags, and open
  the existing full tag manager from an accessible icon button. Load, copy,
  export, rename, and delete remain inline icon actions.
- Each session opens a tag manager using the existing Chat modal surface. Its
  picker appears while the add-tag section is focused and includes separate
  controls to enter a new label and search existing labels. The full available
  list scrolls within the modal, shows session counts in History-style rows,
  supports keyboard selection, and leaves the footer clear. Edits persist
  through the existing session metadata callback.
- These UI changes remain a branch prototype pending live Obsidian review.
- `list_session_tags`, `add_session_tags`, `rename_session_tag`, and
  `remove_session_tags` operate on a specified saved session through the
  shared session state owner. The main chat overflow menu can generate and
  merge tags for the active session.
- Settings bulk generation uses the selected profile, hydrates eligible
  sessions through the shared owner, runs sequentially, preserves tags added
  during generation, and reports progress and skipped/failed sessions inline.
- Its progress modal previews tag chips from the four most recently completed
  sessions, keeps cumulative tagged/skipped/failed counts, and sends one
  contextual screen-reader announcement per successful session.
- Tag edits update the session timestamp so the existing sync comparison can
  detect metadata changes.
