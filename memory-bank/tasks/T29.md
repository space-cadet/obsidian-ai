# T29: Android Background Processing — Streaming Stops When App Backgrounded

**Status:** ⏸️ DEFERRED  
**Priority:** LOW (was HIGH)  
**Created:** 2026-07-28  
**Updated:** 2026-07-28 (investigation complete, deferred)

## Problem

On Android, when the Obsidian app goes into the background (user switches apps, screen turns off, etc.), obsidian-ai stops generating/streaming the AI reply. Other plugins like **AI Tagger Universe** appear to continue working even when the app is backgrounded.

## Expected Behavior

AI reply generation should continue in the background, and the full response should be available when the user returns to the app.

## Actual Behavior

Streaming/generation stops immediately when the app loses foreground focus.

## Investigation Results (2026-07-28)

### AI Tagger Universe Analysis
- **Cloned and examined source code**: https://github.com/Agents365-ai/obsidian-ai-tagger-universe
- **Finding**: It has NO special background handling whatsoever
- Uses `requestUrl()` from Obsidian API (same as any plugin)
- No lifecycle hooks beyond standard `onload`/`onunload`
- No Service Workers, no Background Fetch API, no wake locks
- Event handlers only listen to vault events (`delete`, `modify`, `layout-change`)

### Why It "Works" in Background
AI Tagger Universe doesn't actually do background work. It:
1. Is **user-triggered only** — click button to tag a note
2. Fires **single HTTP request** and waits for response
3. Completes in **2-10 seconds**
4. If user switches apps mid-request, OS gives Obsidian grace period (few seconds) before suspending WebView

It **survives brief backgrounding because it doesn't stream** — one request, one response, done. No persistent connection to break.

### Obsidian API Limitations
The Obsidian API **does not expose** mobile app lifecycle events:

| Available | Not Available |
|-----------|---------------|
| `onload()` | `onResume()` |
| `onunload()` | `onPause()` |
| `workspace.on('layout-change')` | `onBackground()` |
| `vault.on('modify')` | `onForeground()` |

The `Plugin` class extends `Component`, which only provides `onload`/`onunload`.

### Root Cause Confirmed
This is a **platform limitation**, not a plugin bug:
- Android WebView pauses JavaScript execution when app backgrounds
- `setTimeout`/`setInterval` get throttled to 1000ms+ or freeze
- Pending `fetch`/`EventSource` connections abort
- Obsidian provides no hooks for background/foreground transitions

## Decision: DEFERRED

**User decision**: Don't implement complicated solutions. Accept limitation on mobile.

**Rationale**: Any "fix" would require:
- Switching mobile to non-streaming mode (complete UX change)
- Aggressive state persistence (complex, error-prone)
- Native Android service (impossible from Obsidian plugin)
- Battery optimization workarounds (unreliable, user-hostile)

**Trade-off accepted**: Desktop = full streaming experience. Mobile = works but pauses on background. User can re-open app to see completed response (if it finished in grace period) or retry if it didn't.

## Future Options (If Revisited)

1. **Detect mobile + switch to non-streaming**: Use `Platform.isMobileApp`, `requestUrl()`, `stream: false`
2. **Aggressive state persistence**: Save after each message, offer resume on return
3. **User education**: Document that mobile has limitations
