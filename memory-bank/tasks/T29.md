# T29: Android Background Processing — Streaming Stops When App Backgrounded

**Status:** 🔄 IN PROGRESS  
**Priority:** HIGH  
**Created:** 2026-07-28  

## Problem

On Android, when the Obsidian app goes into the background (user switches apps, screen turns off, etc.), obsidian-ai stops generating/streaming the AI reply. Other plugins like **AI Tagger Universe** continue working even when the app is backgrounded.

## Expected Behavior

AI reply generation should continue in the background, and the full response should be available when the user returns to the app.

## Actual Behavior

Streaming/generation stops immediately when the app loses foreground focus.

## Root Cause Analysis

Possible causes:
1. **JavaScript execution paused**: Android WebView may pause JavaScript timers/execution when app is backgrounded
2. **Fetch/stream cancellation**: The HTTP stream connection may be dropped when the app backgrounds
3. **No background service**: Unlike AI Tagger Universe, obsidian-ai doesn't use a background service or keep-alive mechanism
4. **React/component unmount**: Chat component may be unmounting/pausing when the view is hidden

## Reference Implementation

**AI Tagger Universe** apparently handles this correctly. We need to investigate how:
- Does it use a background service?
- Does it use Web Workers?
- Does it use a persistent notification to keep the process alive?
- Does it batch/tag in the background differently?

## Proposed Solutions

1. **Investigate AI Tagger Universe** approach (if open source) or general Android background processing patterns
2. **Use Web Workers** for API calls (runs in separate thread, may survive backgrounding)
3. **Implement request persistence**: Save pending request state, resume on foreground
4. **Use Capacitor/Cordova background mode** plugins (if available in Obsidian mobile)
