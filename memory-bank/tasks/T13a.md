## Overview

**Critical bug**: When the agent used tool calls (e.g., `search_notes`, `read_note`), the results of those tool calls were **not passed as conversation context** in subsequent user messages. The LLM would forget that a tool had executed and its results, leading to:

- Agent asking to search again after already searching
- Agent being unaware of note contents it just read
- Broken multi-turn agent conversations

## Root Cause

In `src/hooks/useMessageActions.ts`, the message history was built by stripping tool call context:

```typescript
const history = messagesRef.current
    .slice(-maxContextMessages)
    .map((m) => ({
        role: m.role as "user" | "assistant",
        content: buildReplayContent(m),  // ← ONLY text content, no tool calls/results
    }));
```

The `buildReplayContent()` function only included `message.content` (plain text) and `message.resolvedParts` (attachments). It completely ignored:
- `message.contentParts` — interleaved text + tool call parts with results
- `message.toolCalls` — array of tool calls and their results

## The Fix

Created `buildHistoryWithTools()` that reconstructs the **full Vercel AI SDK message shape** for tool-enabled conversations:

### Assistant messages with tool calls → expanded into two messages:

1. **`role: "assistant"`** with content parts:
   - `type: "text"` — the assistant's reasoning text
   - `type: "tool-call"` — each tool call with `toolCallId`, `toolName`, `input`

2. **`role: "tool"`** with result parts:
   - `type: "tool-result"` — each result with `toolCallId`, `toolName`, `output: { type: "text", value: ... }`

### Fallback handling:

- Uses `contentParts` (newer interleaved format) when available
- Falls back to `toolCalls` array for older persisted messages
- Plain text messages pass through unchanged

## Lessons Learned

- The Vercel AI SDK requires tool calls and results to be passed as **separate messages** in a specific shape. Simply including text content is insufficient.
- Persisting `contentParts` (interleaved text + tool calls) in `ChatMessage` was the right design choice — it enables accurate history reconstruction.
- When building message history for API calls, always consider whether the LLM needs full tool execution context, not just the final text output.
