## Description
Several built-in tools deliberately limit their results to protect the model
context, but they do not let the agent request the next batch. A repeated call
usually returns the same first results. This task adds a clear continuation
contract so bounded results remain safe without making complete retrieval
impossible.

The current affected tools are:

- `search_notes` — maximum 50
- `list_notes` — maximum 100
- `search_note_content` — maximum 50, with `total_matches` and `truncated`
- `search_web` — maximum 20
- `read_pdf` — default 50 pages, with no starting-page argument
- `list_memories` — caller-supplied limit, newest entries first
- `search_memories` — maximum 50
- `read_memory_audit` — caller-supplied limit, newest entries first
- `search_past_sessions` — maximum 20

`create_notes` and `check_paths` are not part of this result-pagination list:
their limits bound the caller's input batch rather than hiding an unreturned
set of search results.

## Acceptance Criteria
- [x] Each paginated tool has a stable ordering and an explicit page size.
- [x] A result can include `has_more` and a safe `next_cursor` or equivalent
      continuation request.
- [x] Continuation state includes the relevant query, filters, and sort order,
      preventing accidental mixing of unrelated result sets.
- [x] Subsequent pages do not repeat or skip results under the documented
      consistency model.
- [x] `search_note_content` preserves its useful `total_matches` and
      `truncated` information while gaining continuation support.
- [x] `read_pdf` can request a later page range rather than only the first
      `max_pages` pages.
- [x] The agent is instructed to continue only when the user needs more data,
      with a bounded maximum number of pages per request.
- [x] Tests cover first pages, continuation pages, empty final pages, changed
      filters, invalid cursors, and result pairing across both tool transports.
