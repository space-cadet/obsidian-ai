# Task: T24a — Global Search Scope over Index-Only Sessions

*Created: 2026-09-19 23:05:00 IST*
*Last Updated: 2026-10-21 10:45:00 IST*

**Status:** ⏸️ **Pending Decision**
**Priority:** MEDIUM
**Parent:** T24

## Potential Gap — Not Confirmed in Current Use

Index-only startup (T24, `99860e6`) boots sessions from `sessions/index.json`
with `messages: []`; message files hydrate lazily on first open. The search
hook (`src/hooks/useSearch.ts:34-35`) only searches sessions hydrated in
memory — a phrase inside a session that has not been opened since restart
may return no matches if that session's messages have not been hydrated. This
was identified from the index-only architecture and older PR reviews; it has
not been confirmed as a current user-visible failure.

Codex flagged this in all three review waves of PR #8 (P2); deferred twice to
keep the perf PR focused. Deepak directed it be tracked as a subtask of T24
(2026-09-19) rather than a new orphan task.

## Options

- **A — Hydrate-on-search:** on search, load message files for unopened
  sessions, search them, discard (or keep) the hydrated state per result.
  Smallest diff; restores pre-1.6.0 behavior; cost paid only when searching.
- **B — Disk-backed search:** grep the `.jsonl` session files directly
  without touching UI hydration state. No hydration side-effects; more code.
- **C — Ship as-is + visible scope note:** "searching open chats only" hint
  under the search box. Zero work; honest; still a downgrade from 1.5.0.

## Decision

Pending Deepak. Cloudy's lean: **A** — smallest diff, matches old behavior,
cost only paid when someone actually searches.

## Validation Update — 2026-10-21

The user reports that toolbar search finds message content in an older session
from May 14. This confirms that at least that older session was searchable in
their current use. It does not establish whether that session's messages had
already been hydrated, so the unopened/index-only case remains unverified.
Do not describe this as a confirmed current bug without reproducing a miss in
a session whose message payload has not been loaded.
