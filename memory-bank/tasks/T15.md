## Description

Transform the Obsidian AI chat from a single active profile model into a **multi-panel, multi-provider** interface. Each Chat panel instance can be bound to a different provider profile, enabling simultaneous conversations with Gemini (local LLM), Cloudy (remote agent via Tailscale), Ember (phone agent), and any other configured provider.

This is the foundation for the full multi-agent experience. It also requires a **Settings UI overhaul** to display and manage all enabled profiles with their providers, endpoint URLs, and API keys — instead of only showing the currently selected profile's details.

## Architecture

### Before (Single Active Profile)
```
Settings
├── activeProfileId: "gemini-main"
└── profiles: [...]

ChatPanel (1 instance)
├── ChatApp
│   ├── useChat() → reads activeProfileId from Settings
│   └── ChatEngine → single adapter set
```

### After (Per-Panel Profile + Tabs)
```
Settings
├── profiles: [
│   ├── { id: "gemini", provider: "gemini", apiKey: "...", model: "gemini-2.5-flash" }
│   ├── { id: "cloudy", provider: "agent", endpointUrl: "http://100.89.228.41:18789", agentId: "main" }
│   └── { id: "ember", provider: "agent", endpointUrl: "http://ember:18789", agentId: "main" }
│   ]
├── defaultProfileId: "gemini"
└── maxTabs: 5

ChatPanel (multiple instances possible)
├── ChatApp profileId={optional}
│   ├── TabBar
│   │   ├── [💎 Gemini] [×]
│   │   ├── [☁️ Cloudy] [×]
│   │   ├── [🔥 Ember] [×]
│   │   └── [+] — Add tab
│   ├── TabContent (active tab)
│   │   ├── useChat(profileId="cloudy")
│   │   ├── ChatEngine(profileId="cloudy")
│   │   └── MessageList (cloudy messages only)
│   └── TabContent (inactive, hidden)
│       ├── useChat(profileId="gemini")
│       └── ChatEngine(profileId="gemini")
│       └── (preserved but not rendered)
```

## Design Decisions

1. **Per-panel `profileId` over global state** — Each `ChatEngine` instance is fully isolated. No shared mutable state between tabs.
2. **Tab state in `ChatApp`, not `ChatEngine`** — `ChatEngine` remains a pure chat logic class. Tab management is a UI concern.
3. **Settings UI: list view replaces single-profile view** — The old "only show selected profile" UX doesn't scale. List view is necessary for discovering what profiles exist.
4. **Profile picker on "+" tab, not global command** — Users discover the feature naturally by interacting with the tab bar.
5. **Conversation isolation by composite key** — `localStorage` key: `obsidian-ai-chat-${profileId}-${sessionKey}` prevents collisions.
6. **Lazy adapter initialization** — Adapters are only created when a tab is first activated, not at mount time for all tabs.

## Implementation Notes

- **Settings migration**: Existing single `activeProfileId` migrates to `profiles[0]` + `defaultProfileId` on first load.
- **Breaking change**: Old `localStorage` keys won't be automatically migrated. Document this in release notes.
- **Performance**: Inactive tabs' `ChatEngine` instances should not poll or maintain SSE connections. Only the active tab's engine is "live".
- **Mobile consideration**: Tab bar may need horizontal scroll or "more" dropdown on narrow panels.
- **Color coding**: Each provider type gets a subtle color (Gemini = blue, Agent = green, OpenAI = purple) for tab icons.
