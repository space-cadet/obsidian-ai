# T40: Multi-User Chat with LaTeX Support

*Created: 2026-08-08*
*Status: 🔄 IN PROGRESS — Phase 2 Complete (Presence Tracking), Phase 2b Pending*

## Objective

Add real-time multi-user chat capability to obsidian-ai, enabling multiple human users to join a shared chat room within Obsidian. Leverage existing LaTeX rendering, group chat UI, and context system.

## Background

This was one of the original goals of the super-chat/chimera-chat/obsidian-ai ecosystem that got deprioritized while building core chat infrastructure. The codebase is now mature enough to support this feature.

## Architecture Audit Summary

**Read full audit:** `memory-bank/implementation-details/multi-user-chat-audit.md`
**Read design doc:** `memory-bank/implementation-details/multi-user-chat-design.md`

### Key Decision: No Supabase
- **Decision:** Build WebSocket relay + WebRTC peer-to-peer. Reject cloud database.
- **Rationale:** Self-hosted, LAN-capable, no vendor lock-in, aligns with Obsidian local-first philosophy.

### Dual-Backend Architecture
Both backends implement unified `SyncAdapter` interface:
- **WebSocket relay** — for immediate PoP testing (simple, reliable)
- **WebRTC** — for production P2P (lower latency, no server bandwidth)

### What's Already Working ✅
- LaTeX rendering via Obsidian's built-in MathJax/KaTeX
- GroupChatApp component renders multi-participant conversations
- Message types support `agentId`/`agentName`/`agentColor` (maps to user fields)
- Clean `ChatStorage` interface — easy to wrap with sync
- Context/mention system (`@note`, `@folder`, `@tag`)

## Design Principles

1. **Transport Agnosticism** — GroupChatApp knows nothing about WS/WebRTC
2. **LaTeX is Free** — Obsidian already renders `$...$` and `$$...$$`
3. **Reuse, Don't Rebuild** — Map human users to existing AI participant fields
4. **Progressive Enhancement** — WebSocket first, WebRTC later
5. **Room-Based Identity** — Anonymous rooms, no global auth for PoP

## Sync Adapter Interface

```typescript
interface SyncAdapter {
  connect(roomId: string, userId: string): Promise<void>;
  disconnect(): void;
  sendMessage(msg: ChatMessage): Promise<void>;
  onMessage(callback: (msg: ChatMessage) => void): void;
}
```
