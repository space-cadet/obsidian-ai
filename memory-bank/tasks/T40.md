# T40: Multi-User Chat with LaTeX Support

*Created: 2026-08-08*
*Updated: 2026-08-10 22:45 IST*
*Status: 🔄 Phase 2 Complete (Presence Tracking + Bug Fixes), Phase 2b Pending*

## Objective

Add real-time multi-user chat capability to obsidian-ai, enabling multiple human users to join a shared chat room within Obsidian. Leverage existing LaTeX rendering, group chat UI, and context system.

## Background

This was one of the original goals of the super-chat/chimera-chat/obsidian-ai ecosystem that got deprioritized while building core chat infrastructure. The codebase is now mature enough to support this feature.

## Architecture

**Design doc:** `memory-bank/implementation-details/multi-user-chat-design.md`
**Audit doc:** `memory-bank/implementation-details/multi-user-chat-audit.md`
**Presence tracking:** `memory-bank/implementation-details/presence-tracking.md`

### Key Decision: No Supabase
- **Decision:** Build WebSocket relay + WebRTC peer-to-peer. Reject cloud database.
- **Rationale:** Self-hosted, LAN-capable, no vendor lock-in, aligns with Obsidian local-first philosophy.

## Known Bugs (as of 2026-08-10 evening)

### Bug: Remote messages trigger AI response
**Status:** 🔴 OPEN — found during testing
**Description:** When a remote message arrives via relay, `ChatApp.tsx`'s `onMessage` callback adds it to the session state. The chat logic then treats this as a new user message and sends it to the AI for a response. Remote messages should be displayed but NOT forwarded to the AI.
**Likely fix:** Add a `remote: true` or `skipAI: true` flag to remote messages in `WebSocketSyncAdapter`, and check this flag in `ChatApp.tsx` before triggering AI response.
**Related:** T40 Phase 2b — message attribution
