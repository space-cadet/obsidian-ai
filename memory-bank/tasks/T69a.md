## Description

Evaluate and plan support for using a user's ChatGPT/Codex subscription from
Obsidian AI. This must remain distinct from the existing OpenAI API-key
provider. There are now two practical implementation paths: a desktop
adapter that launches the locally installed Codex app-server, and a mobile-
compatible experimental adapter using device authorization and direct HTTP.

## Acceptance Criteria

- [ ] Verify the current official Codex authentication and app-server contract.
- [ ] Reproduce the mobile device-flow approach used by Chatting with AI in a
  small, clearly experimental compatibility probe.
- [ ] Define login, already-authenticated, logout, re-authentication, and
  unavailable-Codex states in the provider settings and diagnostics.
- [ ] Define the desktop process lifecycle, message transport, streaming,
  approvals, tool calls, cancellation, and cleanup behavior.
- [ ] Preserve the existing OpenAI API provider as a separate option.
- [ ] Document the maintenance and support tradeoffs of direct ChatGPT/Codex
  backend calls before deciding whether to ship that mobile path.
- [ ] Define secure handling for account state, tokens, logs, exports, sync,
  and crash/error messages.
- [ ] Provide a bounded proof-of-concept and real-provider acceptance plan
  before production implementation.

## Implementation Details

Codex Panel remains the closest technical reference for the desktop path because
it starts a local `codex app-server` and inherits the user's existing Codex CLI
authentication. Chatting with AI is now a concrete mobile reference: its public
source performs device authorization with Obsidian `requestUrl()`, stores the
credential in `SecretStorage`, refreshes it, and sends buffered HTTP requests to
the Codex backend. This proves mobile feasibility, but its direct backend
protocol should start as an experimental compatibility path because it is not
the documented app-server interface.

References:

- [Chatting with AI README](https://github.com/o1xhack/obsidian-chatting)
- [ChatGPT OAuth service](https://raw.githubusercontent.com/o1xhack/obsidian-chatting/main/src/auth/chatgptOAuth.ts)
- [ChatGPT OAuth API adapter](https://raw.githubusercontent.com/o1xhack/obsidian-chatting/main/src/api/chatgpt-oauth.ts)
- [Codex App Server documentation](https://learn.chatgpt.com/docs/app-server)

The adapter should translate app-server events into the existing turn,
streaming, tool, approval, and persistence contracts. It should not copy the
Codex credential store into plugin settings unless the supported integration
requires it.
