## Description

Evaluate and plan support for using a user's ChatGPT/Codex subscription from
Obsidian AI. This must remain distinct from the existing OpenAI API-key
provider. The first implementation candidate is a desktop adapter that
launches the locally installed Codex app-server and uses its supported login
and session protocol.

## Acceptance Criteria

- [ ] Verify the current official Codex authentication and app-server contract.
- [ ] Define login, already-authenticated, logout, re-authentication, and
  unavailable-Codex states in the provider settings and diagnostics.
- [ ] Define the desktop process lifecycle, message transport, streaming,
  approvals, tool calls, cancellation, and cleanup boundary.
- [ ] Preserve the existing OpenAI API provider as a separate option.
- [ ] Document why direct calls to private ChatGPT/Codex backend endpoints are
  not the default approach and identify the decision required to use one.
- [ ] Define secure handling for account state, tokens, logs, exports, sync,
  and crash/error messages.
- [ ] Provide a bounded proof-of-concept and real-provider acceptance plan
  before production implementation.

## Implementation Details

The recovered August 27 ecosystem comparison identified Codex Panel as the
closest technical reference because it starts a local `codex app-server` and
inherits the user's existing Codex CLI authentication. Chatting with AI is the
closest product comparison but performs its own device authorization and calls
an undocumented backend endpoint; that approach is retained as research only.

The adapter should translate app-server events into the existing turn,
streaming, tool, approval, and persistence contracts. It should not copy the
Codex credential store into plugin settings unless the supported integration
requires it.
