## Description

Evaluate support for using a user's ChatGPT/Codex subscription from
Obsidian AI, separate from the existing OpenAI API-key provider. Mobile users
must be able to sign in and test Codex without a connected desktop or Codex
process. OpenAI's documented Sign in with ChatGPT flow now supports open-source
clients, but its required 127.0.0.1 callback listener is not available to an
Obsidian mobile plugin. Desktop app-server and official open-source OAuth are
separate supported candidates; mobile direct HTTP remains a compatibility
probe until an appropriate supported mobile flow exists. Desktop auth must not
require the Codex desktop application.

## Implementation Details

OpenAI now documents Sign in with ChatGPT for open-source clients. That
flow can authorize eligible Responses API use with a ChatGPT plan, but it
requires a local HTTP callback on `127.0.0.1`; Obsidian mobile does not expose
the inbound listener or Node/Electron APIs needed to receive that callback.
Keep it as a supported desktop candidate alongside the Codex `app-server`.
The desktop GUI is not required; runtime provisioning for `app-server` remains
undecided.

For mobile, implement only a manual compatibility probe, based on the device
authorization path used by the Codex CLI and the public Chatting with AI
reference. It should display the one-time code, poll for authorization, make
one short request through the undocumented Codex response endpoint, and offer
a separate refresh check. Keep credentials in memory only and clear them when
the probe closes. Do not add this path to provider profiles or ordinary chat
requests. This probe does not establish a supported or stable mobile login.

The desktop app-server adapter should translate events into the existing
turn, streaming, tool, approval, and persistence contracts. The mobile probe is
implemented in `src/auth/CodexMobileCompatibilityProbe.ts` and
`src/modals/CodexMobileProbeModal.ts`; its command is available in Developer
Mode. It sends one fixed prompt with a user-selected model and keeps credentials
in memory only. Closing the modal clears the temporary credential; it does not
revoke the app grant. Focused mocked tests and TypeScript pass, but no iOS or
Android device run has been performed. Any production mobile implementation
must choose secure storage supported by its minimum Obsidian version. Never
copy subscription tokens into ordinary settings, exports, or synced data.
Desktop runtime provisioning remains open.
