# Task: T60b
*Created: 2026-08-25 12:52:36 IST*
*Last Updated: 2026-08-25 16:56:00 IST*

## Task Information
**Title:** Cross-Loop Tool Transport Parity
**Status:** 🔄 Diagnosed — three concrete bugs identified, ready for implementation
**Priority:** HIGH
**Created:** 2026-08-25 12:52:36 IST

## Description
Make AI SDK chat, OpenResponses remote agents, and council mode transport the
same resolved tool registry and preserve every tool call/result pair.

## Bugs Identified — 2026-08-25

### Bug 1: Original input is resent on every loop iteration
**Location:** `src/agent/OpenResponsesLoop.ts:92-108`

`streamAgentResponse({ input, tools })` is called inside the `while` loop. The
`input` array contains the full original conversation (system prompt + history +
user message). After a tool-result continuation, the loop returns to the top
and resubmits the entire conversation from scratch.

On a 17-step tool chain, the original input is sent 17 times, causing linear
transcript growth. This is the direct cause of the 500k-token incident.

### Bug 2: The continuation ID is discarded
**Location:** `src/api/AgentApiManager.ts:214-230`

`continueWithToolResult()` accepts `previousResponseId` as a parameter but
never uses it. `AgentApiOptions` has no `previousResponseId` field, and
`streamAgentResponse()` never serializes it to the request body. The code
comment says `// previous_response_id is accepted but currently ignored by
OpenClaw`, but the installed OpenClaw gateway **does** support this field.

Continuations are therefore sent as brand-new stateless requests instead of
stateful continuation calls.

### Bug 3: Continuation handler doesn't handle function calls
**Location:** `src/agent/OpenResponsesLoop.ts:264-282`

After `continueWithToolResult()`, the event handler only processes
`text-delta`, `finish`, and `error` events. It does **not** handle
`function_call` or `function_call_done`. If the model wants to make a second
tool call after seeing the first result, the loop won't catch it.

This forces multi-round tool chains to fall back into the broken outer-loop
path (Bug 1) instead of using true continuation.

## Minimal Fix Spec

### AgentApiManager.ts
1. Add `previousResponseId?: string` to `AgentApiOptions`
2. In `streamAgentResponse()`, serialize it as `body.previous_response_id`
3. In `continueWithToolResult()`, pass `previousResponseId` and `tools`

### OpenResponsesLoop.ts
1. Move the initial `streamAgentResponse({ input, tools })` call **outside**
   the `while` loop — call it exactly once
2. Store the `response_id` from the `finish` event
3. For every subsequent tool round, call only
   `continueWithToolResult(previousResponseId, functionCallOutputs, tools, signal)`
4. Refactor event consumption into one shared handler used by both initial
   and continuation streams. The handler must process:
   - `text-delta` — update UI text
   - `function_call` / `function_call_done` — populate `pendingFunctionCalls`
   - `finish` — capture response ID
   - `error` — throw
5. Fail/stop if a continuation is attempted without a valid response ID

## Impact Analysis
With the fix, a 17-step tool chain goes from:
- **Before:** Original input (~200 tokens) × 17 + accumulated results = ~500k tokens
- **After:** Original input once + 17 stateful continuations = ~3.6k tokens
- **Reduction:** ~140× for multi-step tool chains
