## Problem

`ToolCallNotification.tsx` (`ToolCallDetail()` function) renders expanded tool
result details in chat history. Only 6 tools have dedicated rendering; all
others fall through to a generic `"{tool_name} completed successfully"` string
with no actionable detail.

This means the user cannot see:
- Which note was edited/appended/patched/created/moved/deleted
- Web search results or PDF content previews
- Note content search matches
- Memory search results

## Root Cause

The catch-all fallback at the end of `ToolCallDetail()` does not inspect
`result.content`, `result.path`, or `result.matches` before emitting the
generic string. `ToolExecutor` already returns the correct fields; they are
simply not rendered in the UI.

## Affected Tools

| Tool | Current Display | What `ToolResult` Contains |
|------|-----------------|---------------------------|
| `edit_note` | Generic success | `success`, `path` |
| `append_to_note` | Generic success | `success`, `path` |
| `patch_note` | Generic success | `success`, `path` |
| `create_note` | Generic success | `success`, `path` |
| `move_note` | Generic success | `success`, `path`, `oldPath` |
| `delete_note` | Generic success | `success` |
| `edit_section` | Generic success | `success`, `path` |
| `web_search` | Generic success | `content` |
| `search_note_content` | Generic success | `matches[]`, `total_matches`, `truncated` |
| `read_pdf` | Generic success | `content`, `page_start`, `page_end`, `total_pages` |
| `read_web_page` | Generic success | `content` |
| `read_memory` / `search_memories` / etc. | Generic success | `content` or `matches[]` |

## Target Fix

Replace the final catch-all with a smart fallback chain:

1. **If `result.content` exists** → render truncated preview (500 chars, same as `read_note`)
2. **If `result.path` exists** → render affected path (with `oldPath → path` for moves)
3. **If `result.matches` exists** → render matches table (same as `search_notes`)
4. **Else** → generic success text

Also add explicit `search_note_content` handling since it returns the same
`matches[]` shape as `search_notes`.
