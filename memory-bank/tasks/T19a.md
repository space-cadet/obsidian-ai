## Description
Complete T19 attachment support for multi-agent and multi-user group chats. A user attachment must be sent to the current group agents and remain available when later turns replay the conversation.

## Acceptance Criteria
- [x] Group user messages persist resolved multimodal parts.
- [x] Group agents receive attachment parts on the initial turn and on later replayed turns.
- [x] Relay messages preserve attachment metadata and resolved parts.
- [x] Incoming remote messages preserve fields required for later agent replay.
- [x] Focused tests cover local group replay and relay propagation.
- [x] TypeScript, full tests, and production build pass.

## Implementation Details
Use `ChatMessage.resolvedParts` as the replay representation, matching the single-chat implementation. Thread the parts through `ParticipantRouter` and `Orchestrator.buildContext()`. Group agents currently share the resolved payload produced from the active profile; provider-specific PDF behavior remains governed by `AttachmentEngine`.
