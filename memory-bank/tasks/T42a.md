# T42a: Sync Index — Skip Unchanged Sessions

*Created: 2026-08-19*
*Parent: T42*
*Status: 🔄 Implemented; acceptance review still open*
*Priority: P1*

## Objective

Implement a persisted sync index for obsidian-ai that records session checksums and remote ETags, enabling skip-unchanged optimization. This is the most impactful performance improvement from SyncIt.

## Background

Currently, obsidian-ai's `SyncEngine.computeSyncPlan()` compares all local sessions against all remote sessions on every sync. For a user with 50 sessions where only 2 changed, this wastes time and bandwidth. SyncIt's `SyncIndexManager` solves this by tracking `{localMtime, localSize, remoteETag}` in a JSON file.

## Implementation Plan

### Phase 1: Index Schema
```typescript
interface SessionSyncIndex {
    version: 1;
    serverSignature: string;  // hash of url+username+prefix
    lastSyncTime: number;
    sessions: Record<string, {
        localChecksum: string;   // SHA-256 of session JSON
        localModifiedAt: number; // session.updatedAt
        remoteETag?: string;     // from WebDAV
        remoteModifiedAt?: number;
    }>;
}
```

### Phase 2: Index Operations
- `loadIndex(serverSignature)` — load from IndexedDB or localStorage
- `isUnchanged(session, remoteMeta)` — compare checksum + ETag
- `updateIndex(sessions, remoteMetas)` — rebuild after successful sync
- `clearIndex()` — on server config change

### Phase 3: Integration
- Hook into `SyncEngine.computeSyncPlan()` before comparing sessions
- If index says unchanged → skip (count as "unchanged")
- If index missing or server changed → full comparison (degrade gracefully)

## Acceptance Criteria
- [ ] 50-session vault with 0 changes syncs in <1s (vs. current 5-10s)
- [x] Index invalidates when the recorded server signature changes
- [x] Index survives app restart through plugin data
- [x] Missing or damaged index falls back to a full comparison

## Current Limit

The index is not the source of truth. A separate test is still needed for changing the account, encryption settings, or vault while reusing the same remote path.
