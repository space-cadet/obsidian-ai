# T43: Multi-User and Agent Chat with LaTeX Support

*Created: 2026-08-10*
*Depends on: T40 (Multi-User Chat with LaTeX Support)*
*Status: 🔄 Architecture Design*

## Objective

Evolve the multi-user chat system (T40) to support **equal-footing participants** — both AI agents and remote human users participate in the same chat tab, with messages routed to all participants and each deciding independently how to respond.

**Branch:** `t43-multi-user-agent-chat` (branched from `main` at commit `19f780d`)

## Background

T40 built the WebSocket relay infrastructure (PoP) and presence tracking (Phase 2). The current architecture treats remote users as "connections" rather than first-class participants. Messages sent to the relay are also sent to the local AI, but there's no clean model for:
- Selecting which remote users participate in which tab
- Routing messages to all participants (agents + humans) equally
- Including remote user messages in agent context
- Creating human-only tabs (no AI agents)

This task addresses those gaps.

## Architecture: Equal-Footing Participant Model

### Core Principle
All participants — AI agents, remote users, local user — are treated equally in a chat tab.

### Participants

| Type | Source | How Added | Role |
|------|--------|-----------|------|
| AI Agent | Local agent registry | Agent dropdown (existing) | Receives messages, may respond |
| Remote User | Relay user list | User dropdown (new) | Receives messages via relay |
| Local User | You | Always present | Sends messages, sees all |

### Message Flow

```
User A (Client X) sends message in Tab T1
    │
    ├──► AI Agent A1 (in T1) ──► Receives message + context ──► May respond
    │
    ├──► Relay Server ──► User B (Client Y, Tab T2) ──► Displayed
    │
    └──► Local display (User A sees their own message)

User B (Client Y) sends message in Tab T2
    │
    ├──► AI Agent A1 (in T1) ──► Receives message + context ──► May respond
    │       (remote messages included in context!)
    │
    ├──► Relay Server ──► User A (Client X, Tab T1) ──► Displayed
    │
    └──► Local display (User B sees their own message)
```

### Key Rules

1. **Broadcast to all**: Every message sent in a tab is delivered to ALL participants in that tab
2. **Agents see everything**: AI context includes messages from ALL participants (local + remote)
3. **No AI without agents**: If a tab has NO AI agents, messages go to relay only (no AI trigger)
4. **Remote users are participants**: Not just connections — they have presence, can be selected per-tab

## Implementation Strategy: Two-Step Approach

**Step 1: ParticipantRouter Wrapper** (current focus)
- Create a `ParticipantRouter` class that wraps the existing `Orchestrator`
- Keeps all agent logic untouched — minimal risk
- Adds relay routing for remote users alongside agent dispatch
- Validates the participant model before deeper refactor
- If it breaks: disable wrapper, fall back to old group chat behavior

**Step 2: Refactor Orchestrator** (only if Step 1 validates the model)
- Make `Orchestrator` participant-agnostic directly
- Remove wrapper indirection
- Only if needed for features like remote users in debates or agent-to-remote routing
