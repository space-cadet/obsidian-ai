## Description

Make the active chat tab the single source of truth for the provider profile
and effective model shown and used by the toolbar. Repair legacy-chat model
restoration without mutating shared provider-profile defaults, and remove
duplicated presentation state from the model picker and active chip.

## Acceptance Criteria

- [ ] Resolve identity as session override, last assistant model, then profile default.
- [ ] Recompute identity when the active tab or asynchronously loaded messages change.
- [ ] Derive picker, active chip, and turn execution from the same parent-owned identity.
- [ ] Persist model changes as active-session overrides without changing shared credentials.
- [ ] Match standard toolbar dimensions; show picker icon plus active-assignment count.
- [ ] Show provider and a larger purple model name in the active chip without a processor icon.
- [ ] Preserve searchable recent-model behavior and complete portal/accessibility handling.
- [ ] Add regression tests for legacy chats, selection, tab switching, and shared profiles.

## Implementation Details

Use one pure effective-identity resolver and keep the fallback read-only for
legacy sessions. Do not introduce T70 subtasks or a broad settings migration.
The existing session profile supplies provider identity; historical assistant
messages supply the model where no explicit session override exists. Exact
historical provider reconstruction is outside this task because old messages
do not necessarily contain a separate provider identifier.

The picker remains a presentational control. Its local selection state should
be removed or reduced to transient menu state; ChatApp owns the effective
identity and the session override.
