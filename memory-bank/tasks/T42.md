## Objective

Enable persistent, cross-device synchronization of chat sessions via remote storage backends. Users should be able to access their chat history from any device without relying on local-only storage.

## Motivation

Currently, chat sessions are stored locally in Obsidian's plugin data. This means:
- **No cross-device continuity**: Chats on desktop don't appear on mobile
- **Data loss risk**: Local storage can be corrupted or lost
- **No backup**: No way to recover chat history
- **Multi-device friction**: Users must manually manage sessions per device

## Scope

### In Scope
- Pluggable storage backend architecture (S3-compatible, WebDAV, custom server)
- End-to-end encryption of chat data at rest
- Incremental sync (only changed sessions)
- Conflict resolution for concurrent edits
- Offline queue with sync-on-reconnect

### Out of Scope (for v1)
- Real-time collaborative editing (covered by T40 relay)
- Large file/attachment sync (T19 handles local attachments)
- Automatic cloud provider provisioning

### Key Components

1. **StorageAdapter Interface** - Pluggable backends
2. **SyncEngine** - Delta sync, conflict resolution, encryption
3. **LocalCache** - IndexedDB / localStorage for offline support
4. **EncryptionLayer** - AES-256-GCM with user-provided passphrase

## Security Model

### Encryption
- **At rest**: AES-256-GCM, key derived from user passphrase
- **In transit**: HTTPS/TLS (handled by backend)
- **Key management**: Passphrase never stored, only derived key in memory

### Privacy
- Server never sees plaintext (zero-knowledge)
- Metadata (session count, timestamps) may be visible depending on backend
- User controls backend selection and credentials

## Configuration

```typescript
interface RemoteStorageConfig {
    enabled: boolean;
    backend: "s3" | "webdav" | "custom";
    encryption: {
        enabled: boolean;
        passphrase?: string; // Prompted if not set

    syncInterval: number; // minutes, 0 = manual only
    s3?: {
        endpoint: string;
        bucket: string;
        region: string;
        accessKeyId: string;
        secretAccessKey: string;
    };
    webdav?: {
        url: string;
        username: string;
        password: string;
    };
    custom?: {
        url: string;
        apiKey: string;
    };
}
```
