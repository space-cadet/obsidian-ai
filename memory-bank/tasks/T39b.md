## Description

Implement a compatible Obsidian Git provider using the existing mobile-safe
GitManager/isomorphic-git subsystem. The provider must expose bounded,
reviewable Git operations to Obsidian AI while retaining all Git credentials
and Git-specific configuration within the Git plugin.

## Acceptance Criteria

- [ ] Expose a versioned public provider API without requiring Obsidian AI to
  import private Git-plugin source files.
- [ ] Provide `git.status`, `git.changed_files`, and `git.log` as read-only
  capabilities with compact, redacted results.
- [ ] Provide explicit-path staging and commit planning before implementing
  mutation execution.
- [ ] Present pull and push as separate high-risk operations with progress,
  cancellation where supported, and explicit approval.
- [ ] Do not expose force-push, arbitrary remotes, credentials, clone/init, or
  blanket `sync` to the model in the first release.
- [ ] Reuse the Git plugin's existing operation core for both its sidebar and
  provider API, with tests for desktop and mobile-safe paths.

## Implementation Details

- Refactor GitManager's UI-coupled progress handling into typed progress events
  that either the Git UI or the AI tool card can render.
- Preserve the configured repository, branch, author, and authentication within
  the Git plugin. The AI passes structured operation inputs only.
- Replace the human-oriented combined sync flow with explicit tool operations:
  inspect, stage named paths, commit, then optionally pull or push after
  separate confirmation.
