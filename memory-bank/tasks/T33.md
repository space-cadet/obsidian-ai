## Problem

Desktop workspace restoration could retain multiple `obsidian-ai-chat-view` leaves. Each leaf mounted a functioning copy of the shared internal-tab chat UI, leaving a persistent duplicate in the right sidebar.

## Resolution

- On `Workspace.onLayoutReady`, retain one canonical chat leaf and detach stale duplicates.
- Prefer the focused chat leaf when it is one of the restored leaves; otherwise retain the first one.
- Serialize concurrent chat-activation requests so only one caller can create or reveal the singleton view.
- Run the same duplicate cleanup before and after the restoration-frame wait in activation.
