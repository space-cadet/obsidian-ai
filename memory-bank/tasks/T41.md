## Description

Build a complete custom auto-updater for the obsidian-ai plugin that can check for updates from GitHub releases, download and install them, and rollback on failure. Support both stable and dev (pre-release) channels with automatic or manual update modes.

## Acceptance Criteria
- [x] Check GitHub releases for updates via API
- [x] Support stable vs dev (pre-release) channels
- [x] Auto-install stable updates silently (optional toggle)
- [x] Manual check with "Check Now" button in settings
- [x] Backup current plugin before install, rollback on failure
- [x] Cross-platform: works on desktop AND mobile
- [x] Semver comparison for version detection
- [x] Non-semver dev tags handled (e.g., `latest-dev`)
- [x] Commit-hash comparison to prevent perpetual "update available" on dev channel
- [x] Test auto-updater end-to-end with actual release

## Implementation Details

### Architecture
- `src/updater/PluginUpdater.ts` — Core updater class
  - Fetches releases from GitHub API
  - Compares versions using semver
  - Downloads release asset
  - Backs up current installation
  - Extracts and installs new version
  - Rolls back on failure
- `src/settings-sections/updaterSettings.ts` — Settings UI
  - Channel selector (stable/dev)
  - Auto-install toggle
  - Manual "Check Now" button
  - Version display with channel suffix
  - Update metadata modal showing commit hash, message, author, and timestamp

### Key Design Decisions
- **Cross-platform:** Uses `requestUrl` + `app.vault.adapter` instead of Node.js `fs`/`https`
- **Mobile-safe:** No Node.js imports; pure Obsidian APIs
- **Backup strategy:** Copies current `main.js` + `manifest.json` + `styles.css` before install
- **Rollback:** Restores backup files if new version fails to load

### 2026-08-19: Intermittent Update Detection Fix
**Symptom:** Auto-update works once (A→B), then fails next time (B→C). Manual update "resets" it.

**Root cause:** GitHub API response caching — after the first check, subsequent requests within a time window could return stale release data showing the old commit.

**Fixes applied:**
1. **Cache-busting** (`&_cb=${Date.now()}`) added to ALL GitHub API calls (releases + commits + latest stable)
2. **HTTP error handling** — `fetchJson()` now checks status codes and throws on errors
3. **Diagnostic logging** — `PluginUpdater` accepts `UpdaterLogger` interface; all diagnostics go to `debug.log` (visible on mobile via Settings → Diagnostics)
4. **Rate limit detection** — Distinguishes 403 rate limit from other errors in user-facing messages

**Commits:** `b582dfa` (diagnostics), `8ae8650` (logger integration), `fe3f529` (test commit), `f70d950` (test commit 2), `dc0f173` (cache-busting on stable channel)

## Issues and Blockers
- **Dev channel perpetual "update available"**
  - Root cause: `latest-dev` is non-semver, so `compareVersions("latest-dev", "1.2.5")` always returns > 0
  - **Fix applied:** `checkForUpdate()` now accepts `currentCommitHash` parameter. For dev channel, fetches latest commit SHA from GitHub API (`repos/{repo}/commits/main`), compares with local `GIT_COMMIT_HASH`. If match, returns `hasUpdate: false` with `commitMatch: true`.
  - Files modified: `src/updater/PluginUpdater.ts`, `src/main.ts`
  - **Status:** ✅ Fixed and verified — `latest-dev` release rebuilt from ae09179

- **Intermittent update detection failure (2026-08-19)**
  - Root cause: GitHub API CDN caching responses without cache-busting query params
  - **Fix applied:** All API calls now include `&_cb=${Date.now()}` + HTTP status checking + debug logging to `debug.log`
  - **Status:** ✅ Fixed and verified through test commits fe3f529 → f70d950 → dc0f173
