## Description

Create a standalone CLI test harness that can exercise the obsidian-ai plugin's AI features without requiring Obsidian runtime. This enables testing of:
- Attachment resolution (markdown, image, PDF) → multimodal content parts
- Provider API calls (Gemini, OpenAI, Anthropic, etc.) with real API keys
- Streaming responses and tool calling
- Token estimation accuracy

## Status
✅ **COMPLETE** | **Updated:** 2026-05-29

## What Was Built

Instead of standalone CLI scripts, a **Vitest-based E2E test suite** was created. This is superior because:
- Runs via `pnpm test:e2e` (consistent with existing test workflow)
- Skips tests automatically when provider keys are missing
- Supports all existing test infrastructure (coverage, watch mode, CI)
- No need for `tsx` or separate Node.js script execution

## How to Run

```bash
# Copy .env.example to .env and fill in your API keys
cp .env.example .env
# Edit .env with your keys

# Run all e2e tests
pnpm test:e2e

# Watch mode
pnpm test:e2e:watch
```

Tests automatically skip providers whose keys are not configured.

- **Test timeout**: 60 seconds per test (LLM APIs can be slow).
- **CI ready**: Can run in GitHub Actions with repository secrets.
- **PDF tests**: Require a real PDF file at `e2e/fixtures/test.pdf` — currently skipped.
- **Thinking mode**: Only DeepSeek and Claude 3.7 support reasoning/thinking via providerOptions.
