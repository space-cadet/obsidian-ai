## Description

Prevent context window overflows by tracking estimated token usage across conversation history and attached context. Provides truncation and a basic summarisation fallback. Adds a visual indicator in the chat UI showing how much context budget remains.

## Status
⬜ NOT STARTED

## Priority

## Dependencies
- T1 (Chat Panel) — context usage indicator lives in the UI
- T2 (Conversation Chain) — history is what gets truncated

## Completion Criteria

- ⬜ `tokenEstimator.estimateTokens(text: string): number` — rough chars/4 approximation
- ⬜ Per-model context window size table in settings (or configurable override)
- ⬜ `ConversationManager.buildLangChainMessages()` checks total estimated tokens before returning
- ⬜ If over budget: drop oldest turns (keep system prompt + last N turns)
- ⬜ If still over budget after dropping turns: truncate oldest retained message content
- ⬜ Context bar shows token usage indicator: `[Context: ~2,400 / 8,000 tokens]`
- ⬜ Colour coding: green < 60%, amber 60–85%, red > 85%
- ⬜ Truncation is transparent to user (no error, just silently drops old turns)
- ⬜ Dropped turns noted in conversation log (not sent to LLM but visible in UI)

## Context Window Reference

| Model family | Default context window |
|---|---|
| GPT-4o | 128,000 tokens |
| GPT-4o-mini | 128,000 tokens |
| Claude 3.x | 200,000 tokens |
| llama3.2 (Ollama) | 128,000 tokens |
| Gemini 1.5 | 1,000,000 tokens |

For v1: single configurable `maxContextTokens` setting (default 8,000 — conservative to keep costs low). Per-model defaults deferred.

## Token Budget Allocation

```
Total budget: 8,000 tokens (configurable)

Allocation:
  System prompt:     ~500  (fixed)
  Context notes:    ~2,000  (truncated by ContextEngine, T3)
  Conversation:     ~4,500  (oldest turns dropped)
  Response reserve: ~1,000  (headroom for AI output)
```
