# T67: Storage Lifecycle Decomposition

*Created: 2026-08-30*
*Last Updated: 2026-08-30*

**Status**: 🔄 **IN PROGRESS — persistence and sync slices extracted**
**Priority**: HIGH
**Dependencies**: T46, T57, T58d, T65

## Description

Reduce the responsibility overload in `src/lifecycle/storage.ts` by moving
complete storage concerns behind explicit lifecycle boundaries while keeping
startup, persistence, sync, recovery, and session-end behavior unchanged.

## Progress

- [x] Extract settings and chat-data persistence into
      `src/lifecycle/persistence.ts`.
- [x] Add focused characterization coverage for persistence behavior.
- [x] Extract sync orchestration and progress translation into
      `src/lifecycle/sync.ts` (coordination with T58d).
- [ ] Extract selected plugin-data targets, recovery, and conflict handling in
      coordination with T57/T57d.
- [ ] Reassess initialization and session-end intelligence ownership with T65.

## Boundaries

The intended boundaries are initialization, chat persistence, sync
orchestration, selected plugin-data handling, and session-end intelligence.
Extraction must preserve logging, error behavior, queued writes, backup
rotation, search invalidation, cancellation, and lifecycle ownership.

## Acceptance criteria

- [ ] Each extracted boundary has focused tests covering success and failure
      behavior.
- [ ] `storage.ts` remains a coordinator with explicit dependencies rather
      than a second implementation of persistence or sync policy.
- [ ] Sync and plugin-data behavior remain owned by T57/T58d contracts.
- [ ] T65 memory/session behavior is not duplicated during extraction.
- [ ] Focused tests, the full suite, TypeScript, production build, and relevant
      runtime checks pass.
