# T28: Fix Obsidian Note Link Click Crash

**Status:** ✅ COMPLETED  
**Completed:** 2026-07-28
**Priority:** HIGH  
**Created:** 2026-07-28  

## Problem

When the agent returns a message containing a link to an Obsidian note (e.g., `[[Note Name]]` or `obsidian://` links), clicking the link crashes the entire Obsidian app instead of opening the note.

## Expected Behavior

Clicking an Obsidian wiki-link `[[Note Name]]` or internal link should navigate to that note within Obsidian.

## Actual Behavior

The entire Obsidian application crashes when clicking the link.

## Root Cause Analysis

Likely one of:
1. **Markdown rendering**: The link is rendered as a standard `<a>` tag but without proper Obsidian navigation handling
2. **Event handler missing**: No `click` handler intercepts the link to use Obsidian's `app.workspace.openLinkText()` API
3. **Unsafe URL handling**: The renderer or link interceptor may be throwing an unhandled exception
4. **React error boundary not catching**: Crash happens outside the ErrorBoundary scope

## Files to Investigate

- `src/components/ChatMessages.tsx` — message rendering, link handling
- `src/components/MessageBubble.tsx` — individual message bubble component
- Any markdown rendering utility — how links are processed
- `src/main.ts` — plugin-level event handlers

## Proposed Fix

1. **Intercept link clicks** in chat messages
2. **Use Obsidian API** (`app.workspace.openLinkText()`) for wiki-links
3. **Add error handling** to prevent crashes
4. **Test** with various link formats: `[[Note]]`, `[[Note|Alias]]`, `obsidian://open?vault=...`

## Acceptance Criteria

- [ ] Clicking `[[Note Name]]` opens the note without crashing
- [ ] Clicking `[[Note|Alias]]` opens the correct note
- [ ] Clicking external URLs opens in browser (not Obsidian)
- [ ] No app crashes from any link interaction
