## Description

Establish unit test coverage for the streaming, token estimation, and message rendering logic that was fixed in the 2026-07-14 session. The project currently has **zero project-level unit tests** (vitest is configured but only `node_modules` contain `.test.*` files). This task creates the foundation for testing the core streaming pipeline without requiring Obsidian runtime or live API calls.

## Background

Three bugs were fixed in the 2026-07-14 session:
1. **Tool call cards not rendering during OpenResponses streaming** — `OpenResponsesLoop.ts` reset `accumulatedText` per step, breaking `contentParts` accumulation
2. **Token count frozen during AgentLoop streaming** — `AgentLoop.ts` only counted tokens at step boundaries, not during `text-delta` events
3. **StreamingBubble remaining-text logic + React root leaks** — `lastIndexOf` could return `-1` across step boundaries; `createRoot` had no cleanup

These bugs all share a common trait: they involve **async streaming state accumulation** that's hard to verify manually and impossible to catch with TypeScript alone.

## Decisions

### Why Not E2E-Only?
E2E tests (T21) require API keys and network calls. These unit tests run offline, in milliseconds, and catch regressions before commit.

### Why Extract Functions Instead of Mocking Obsidian?
`MarkdownRenderer` and `createRoot` require DOM + Obsidian API mocks. Extracting pure functions lets us test the logic without mocking the rendering layer.

### Priority Rationale
This task is **PENDING** because:
1. The fixes are already verified by build + manual QA
2. The project has no existing unit test culture (only E2E)
3. The highest-value tests (Phase 2) require refactoring that could introduce new bugs
4. Better to defer until after the next release cycle
