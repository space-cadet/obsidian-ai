# T23 — Settings.ts Decomposition
*Created: 2026-05-28 23:05 IST*
*Status: ✅ COMPLETE*

## Problem Statement
`src/settings.ts` has grown to **1,187 lines / 34 KB**. It contained types, defaults, helpers, AND the 836-line `ObsidianAISettingsTab` UI class. A settings configuration file should not contain nearly 1,000 lines of UI rendering logic.

## Root Cause
The `ObsidianAISettingsTab` class handled provider profiles, model config, API keys, web search, debug toggles, and diagnostics — all inline. Each feature added more settings blocks, and the file grew linearly.

## Refactoring Plan

### Phase 1: Extract `ObsidianAISettingsTab` to Dedicated File ✅ COMPLETE
Moved the entire settings tab class out of `settings.ts`.
- **File created:** `src/settings-sections/SettingsTab.ts` (87 lines)
- **Imports updated:** `main.ts` now imports from `./settings-sections/SettingsTab`
- `settings.ts` re-exports for backward compatibility

### Phase 2: Decompose SettingsTab into Section Builders ✅ COMPLETE
Broke the monolithic `display()` method into 8 focused section files.
- **Files created:**
  - `src/settings-sections/hero.ts` (45 lines) — hero banner with active profile info
  - `src/settings-sections/providerProfiles.ts` (35 lines) — React ProfileList mount
  - `src/settings-sections/chatDefaults.ts` (91 lines) — context, auto-name, limits
  - `src/settings-sections/agentTools.ts` (59 lines) — tools toggle, auto-apply, max steps
  - `src/settings-sections/webSearch.ts` (104 lines) — provider dropdown, API keys
  - `src/settings-sections/advanced.ts` (64 lines) — prompts, message history
  - `src/settings-sections/customCommands.ts` (81 lines) — slash command CRUD
  - `src/settings-sections/diagnostics.ts` (189 lines) — metrics, debug level, clear history
- **Shared helpers:** `src/settings-sections/helpers.ts` (46 lines) — `createSection`, `getProviderLabel`
- **Pattern:** Each section exports `renderXSection(containerEl, plugin, saveSettings, ...)` that appends to container

### Phase 3: Keep `settings.ts` as Pure Config ✅ COMPLETE
`settings.ts` now contains only:
- Type definitions (`ProviderType`, `ProviderProfile`, `ObsidianAISettings`, etc.)
- Default values (`DEFAULT_SETTINGS`, `DEFAULT_PROFILES`)
- Pure helper functions (`getDefaultModel`, `getDefaultEndpoint`, `normalizeSettings`, `createProviderProfile`)
- Legacy migration logic
- Re-export of `ObsidianAISettingsTab` for backward compatibility

## Decisions

### Section Function Signature
Each section receives `(containerEl, plugin, saveSettings, ...)` rather than a class instance. This keeps sections decoupled from the tab class and makes them testable in isolation (though we didn't write tests for settings sections — the UI is mostly Obsidian Setting API calls).

### Backward Compatibility
`settings.ts` re-exports `ObsidianAISettingsTab` from `./settings-sections/SettingsTab` so existing imports don't break. `main.ts` was updated to import directly from the canonical location for clarity.

### Dead Code Removal
`renderModelPicker` was a private method (~120 lines) that was never called in `display()`. It appears to be leftover from before the React ProfileList refactor. Removed it entirely. If needed, the React ProfileList component handles model picking.
