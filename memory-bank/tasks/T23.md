# T23 — Settings.ts Decomposition
*Created: 2026-05-28 23:05 IST*
*Status: 🔄 IN PROGRESS*

## Problem Statement
`src/settings.ts` has grown to **1,187 lines / 34 KB**. It contains:
- Lines 1–351: Types, interfaces, helpers, defaults, normalization — reasonable
- Lines 352–1,187: `ObsidianAISettingsTab` class — **836 lines of UI settings tab code**

A settings configuration file should not contain nearly 1,000 lines of UI rendering logic.

## Root Cause
The `ObsidianAISettingsTab` class handles provider profile management, model configuration, API key inputs, web search provider selection, debug toggles, onboarding settings, and more — all inline in one class. Each feature added a new `settingTab.addSetting()` block, and the file grew linearly.

## Refactoring Plan

### Phase 1: Extract `ObsidianAISettingsTab` to Dedicated File
Move the entire settings tab class out of `settings.ts`.
- **Lines to extract:** ~836 lines (lines 352–1,187)
- **Target file:** `src/settings/SettingsTab.ts`
- **Imports to update:** `settings.ts` → `settings/SettingsTab.ts`
- `main.ts` and any other imports of `ObsidianAISettingsTab` must update their import paths

### Phase 2: Decompose SettingsTab into Section Builders
Break the monolithic `display()` method into smaller builder functions or classes.
- **Target files:**
  - `src/settings/sections/ProviderSection.ts` — provider profile CRUD, API keys, endpoints
  - `src/settings/sections/ModelSection.ts` — model selection, discovery, defaults
  - `src/settings/sections/FeatureSection.ts` — auto-apply, auto-name, web search, debug
  - `src/settings/sections/AppearanceSection.ts` — theme, compact mode, onboarding
- **Pattern:** Each section exports `buildSection(container, plugin, settings)` that appends its settings to the container

### Phase 3: Keep `settings.ts` as Pure Config
`settings.ts` should only contain:
- Type definitions (`ProviderType`, `ProviderProfile`, `ObsidianAISettings`, etc.)
- Default values (`DEFAULT_SETTINGS`, `DEFAULT_PROFILES`)
- Pure helper functions (`getDefaultModel`, `getDefaultEndpoint`, `normalizeSettings`, `createProviderProfile`)
- Legacy migration logic
