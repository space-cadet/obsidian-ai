*Created: 2026-08-21*

*Last Updated: 2026-08-22 22:17 IST*

## Objective

Address three architectural issues identified after T43/T55 delivery:
1. Rename "Multi-User Sync" settings section to "Multi-User Chat Relay" for clarity
2. Unify plugin data management so export/import and remote sync use the same serialization logic
3. Begin global reorganization of ad-hoc sync/storage/export-import code into a coherent, modular architecture

## Changes

### 1. Rename Settings Section ✅
- `syncSettings.ts`: Title changed from "Multi-User Sync" → "Multi-User Chat Relay"
- `SettingsTab.ts`: Nav label changed from "Multi-User Sync" → "Multi-User Chat Relay"
- DOM ID updated to `obsidian-ai-settings-multi-user-chat-relay`

### 2. Create PluginDataManager ✅
New file: `src/data/PluginDataManager.ts`

Unified manager for all plugin data serialization/deserialization:
- `createExportBundle(includeSecrets)` — for backup/export (adds schema metadata, redacts secrets)
- `createSyncBundle()` — for remote sync (lightweight, strips API keys when disabled)
- `applyExportBundle(bundle)` — merges import data into settings
- `applySyncBundle(bundle)` — merges remote data into settings
- `validateImport(data)` — schema validation

Internal helpers:
- `extractSettings()` — component-aware settings filtering (used by both export and sync)
- `mergeSettings()` — credential-preserving merge with conflict resolution
- `redactSensitiveValues()` — replaces sensitive keys with "REDACTED"

### 3. Refactor Callers ✅
- `exportImport.ts`: Replaced `exportSettings()`, `validateImportedSettings()`, `mergeSettings()` with PluginDataManager calls. Removed ~80 lines of duplicated logic.
- `main.ts`: Replaced `_serializePluginData()` (~80 lines) and `_deserializePluginData()` (~50 lines) with one-line delegations to PluginDataManager.

## Notes

### What Was Removed
- `exportImport.ts`: `exportSettings()`, `validateImportedSettings()`, `mergeSettings()`, `redactSensitiveValues()`, `deepClone()`, `SENSITIVE_KEYS` — all moved to PluginDataManager
- `main.ts`: `_serializePluginData()` and `_deserializePluginData()` inline implementations — replaced with PluginDataManager delegation

### What Was Preserved
- `main.ts` `_syncTextFile()` — still handles individual file sync (memory.json, persona.md, audit.jsonl)
- `main.ts` `syncPluginData()` — orchestration logic unchanged, just uses manager for serialization
- Export/import UI flow unchanged — only underlying implementation changed

### Future Work — Still Open
The PluginDataManager is the foundation for further unification. Next steps could include:
- Moving `_syncTextFile()` into a FileSyncManager
- Unifying the sync index handling (currently split between SyncEngine and PluginDataManager)
- Adding delta sync for individual components instead of full-bundle sync

### Security and Recovery Limits

- The shared settings manager does not make every remote file encrypted; auxiliary files still use the separate text-file path.
- Deletion records, recovery copies, and per-file conflict choices are not yet implemented.
- This task is a first reorganization pass, not a complete rewrite of the sync system.
