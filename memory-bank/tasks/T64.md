## Description

Standalone benchmark harness for measuring and optimizing token usage in chat
sessions without requiring the full Obsidian runtime. The harness runs
outside the plugin, using the same context-building code paths, to enable
rapid iteration on compaction strategies, budget policies, and tool-result
handling.

This is a **cross-cutting infrastructure task** that serves multiple
workstreams: T48 (compaction), T48a (budget builder), T48d (usage display),
T6a (token accuracy), and T60d (search defaults). It is deliberately a
standalone top-level task rather than a T48 subtask to keep boundaries clean
and allow independent completion.

## Acceptance Criteria

- [ ] Level 1 harness (no API calls): loads session fixtures, reconstructs
  model-facing history using `buildBudgetedHistory` and `buildHistoryWithTools`,
  measures token counts per strategy
- [ ] Fixture library covers at minimum: long coding sessions, multi-tool
  research sessions, attachment-heavy conversations
- [ ] Strategy matrix tests: sliding window, tool eliding, compaction,
  budget caps, deduplication
- [ ] Reports tokens per strategy, messages dropped, and quality metrics
- [ ] Level 1 runs complete in <5 seconds per fixture on typical hardware
- [ ] Level 2 harness (optional, live API): replays fixtures through real
  provider calls, captures provider-reported usage for estimate validation
- [ ] Harness code lives in `benchmarks/` directory, imports directly from
  `src/context/*` and `src/lib/*` — no Obsidian runtime dependency
- [ ] Documented in `memory-bank/implementation-details/context-benchmark-harness.md`
