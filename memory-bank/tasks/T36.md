# T36: Stable Per-Tab Model Selection and Restored Chat View State
*Created: 2026-08-05*
*Completed: 2026-08-05*

**Status:** ✅ **COMPLETED**
**Priority:** HIGH

## Problems

- Changing models in tabbed chat caused a feedback loop between the shared picker and session persistence. The ActionBar debug statement made the oscillation visible as an alternating participant count flood.
- Reloading Obsidian or the plugin restored the conversation data but not the open tab set or each tab's message-list position.

## Implemented Contract

- Selecting a tab restores that tab's profile selection once. The matching picker update is explicitly suppressed from writing back into the session; subsequent user picker changes persist normally. Session writes are also no-ops when their profile state already matches.
- Removed the ActionBar console debug output.
- `StoredChatData` persists ordered saved `openSessionIds`; JSONL index storage persists the same state and a per-session `scrollPosition`.
- **Restore chat tabs after reload** is a default-on Chat Defaults option. With it enabled, reload restores saved open tabs, the active tab, and each tab's scroll offset. Draft tabs are intentionally excluded because they are not saved conversations.
