## Implementation Options

### Option A: Tailscale (Recommended)

**Pros:**
- Free for personal use (20 devices)
- Magic DNS out of the box (`cloudy`, `ember`, `sage-macbook`)
- Single binary, minimal footprint on VPS
- Built for infrastructure / developer use
- ACLs for fine-grained access control

**Cons:**
- Requires new account if not already using

**Steps:**
1. Sign up at tailscale.com
2. Install on MacBook: `brew install tailscale` or download from tailscale.com
3. Install on VPS: `curl -fsSL https://tailscale.com/install.sh | sh`
4. Install on Android: Play Store / Tailscale app
5. Login with same account on all three
6. Enable Magic DNS in admin console
7. Test: `curl http://cloudy:18789/v1/responses` from MacBook

### Option B: NordVPN Meshnet

**Pros:**
- Already paying for NordVPN (no extra cost)
- Same device limit

**Cons:**
- Requires NordVPN app on all devices (heavier than Tailscale)
- No built-in Magic DNS (need manual IP mapping or /etc/hosts)
- Full NordVPN client on VPS is problematic (see below)
- Designed for consumers, less infrastructure-friendly

**Steps:**
1. Enable Meshnet in NordVPN settings on MacBook
2. Enable Meshnet on Android NordVPN app
3. On VPS: install minimal NordVPN client, enable Meshnet without connecting VPN tunnel
4. Record virtual IPs from `nordvpn meshnet peer list`
5. Add to plugin config manually (no DNS names)

## Decision

**Use Tailscale.** It's purpose-built for this exact use case (connecting devices across networks for infrastructure access). The Magic DNS alone saves configuration complexity.

## Notes

- **Security:** Do NOT expose OpenResponses endpoint to public internet. Tailscale keeps it private.
- **VPS:** Only install Tailscale, not full NordVPN. The VPS needs its public IP for other services.
- **Android:** Tailscale app runs in background. May need battery optimization exclusion.
- **Fallback:** If Tailscale fails, use direct public IP for Cloudy (already has one) and WiFi-local IP for Ember.
