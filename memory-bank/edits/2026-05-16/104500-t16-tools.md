## T16: Enable Tool Calling in Group Chat

### Problem
Group chat (council mode) was not using tool calling. The `Orchestrator.sendToAgent()` method used `api.streamChat()` which has no tool support. This meant agents in group chat couldn't read notes, search, edit, etc.

### Solution
Wired up the existing `AgentLoop` (already used by single-user chat) into the `Orchestrator`.

### Changes

**`src/agent/Orchestrator.ts`** (+96 lines):
1. Imported `AgentLoop`, `ToolExecutor`, `noteTools`
2. Added `toolExecutor?: ToolExecutor` to `OrchestratorOptions`
3. Added `toolExecutor` property to `Orchestrator` class
4. Updated `dispatch()` to accept optional `AbortSignal`
5. Replaced simple `streamChat` path in `sendToAgent()` with conditional:
   - When `enableTools && toolExecutor`: use `AgentLoop.run()` with `noteTools`
   - Otherwise: keep original `streamChat` behavior
6. Added tool descriptions to `buildSystemPrompt()` when tools enabled
7. Added tool call approval logic: auto-approve if `autoApprove` enabled; otherwise reject with helpful error message
8. `AgentResponse` now includes `toolCalls` array

**`src/components/ChatApp.tsx`** (+5 lines):
1. Pass `toolExecutor: new ToolExecutor(plugin.app)` to `Orchestrator` constructor
2. Pass `controllerRef.current?.signal` to `orchestrator.dispatch()`
3. Surface `response.toolCalls` in group chat assistant messages

### Safety: Single-User Path Untouched
- `AgentLoop.ts` — no changes
- `api.ts` — no changes
- Single-user `handleSend` branch (~250 lines) — zero modifications
- Group chat branch uses the same `AgentLoop` class instances, just created inside `Orchestrator`

### Known Limitations
- Manual tool approval UI (`PendingToolCard`) is not shown in group chat. If `autoApprove` is off, tools are rejected with a message telling the user to enable auto-approve.
- This is acceptable for MVP; future enhancement could add per-agent pending tool cards.
