#### 10:15:00 IST — T13: Tool result rendering and schema fixes
- **Code commit**: `731e1dc` — `fix(tools): include full paths in tool results, fix search_content, folder depth, ambiguity warnings`
- Files changed: `src/agent/AgentLoop.ts`, `src/agent/ToolExecutor.ts`, `src/agent/tools.ts`, `src/agent/types.ts`
- Build: ✅ tsc + esbuild pass cleanly

## Fixes Applied

### 1. Full path rendering in `list_notes` and `search_notes`
**Problem**: `formatToolResult()` rendered `[[${basename}]]` only. In vaults with duplicate basenames across folders, LLM couldn't distinguish `Research/Papers.md` from `Daily/Papers.md`.
**Fix**: Changed to `[[${path.replace(/\.md$/, "")}]]` — full folder path included.
**File**: `src/agent/AgentLoop.ts` (`formatToolResult`, cases "list_notes" and "search_notes")

### 2. Full path in `get_note_metadata` wiki-link
**Problem**: Used `result.basename ?? result.path` which lost folder context.
**Fix**: Changed to `result.path.replace(/\.md$/, "")`.
**File**: `src/agent/AgentLoop.ts` (`formatToolResult`, case "get_note_metadata")

### 3. Removed broken `search_content` parameter
**Problem**: `search_notes` tool had `search_content: boolean` claiming to search note bodies. Implementation silently returned `false`:
```typescript
if (searchContent) {
    // Note: content search is expensive; we'll read and check
    // For now, skip content search to avoid I/O blocking
    return false;
}
```
This misled the LLM into believing it could search content when it couldn't.
**Fix**: Removed `search_content` from Zod schema, tool description, `ToolExecutor.searchNotes()` signature, and `execute()` case branch.
**Files**: `src/agent/tools.ts`, `src/agent/ToolExecutor.ts`

### 4. `list_folders` depth consistency
**Problem**: `list_folders()` (no args) showed top-level only (depth 1), but `list_folders({path: "Research"})` showed full subtree at any depth.
**Fix**: Rewrote logic so both modes show only immediate children:
- Root: `parts[0]` only
- Parent: `parentPath + "/" + relativeParts[0]` only
**File**: `src/agent/ToolExecutor.ts` (`listFolders()`)

### 5. Ambiguity detection in `resolveNote`
**Problem**: `metadataCache.getFirstLinkpathDest()` returns first match when multiple notes share the same basename. Agent silently reads wrong note.
**Fix**: Added `findAmbiguousMatches()` helper. After wiki-link resolution, checks for duplicate basenames. If ambiguous, attaches `__ambiguous` array to file object. `readNote()` detects this and returns `warning` field in `ToolResult`.
`formatToolResult()` surfaces warning as blockquote:
```
> ⚠️ Ambiguous name: 2 notes share the basename "Papers". Reading "Research/Papers.md".
> Other matches: Daily/Papers.md. Use the full path (e.g., "Folder/Papers") to target a specific note.
```
**Files**: `src/agent/ToolExecutor.ts`, `src/agent/AgentLoop.ts`, `src/agent/types.ts`
